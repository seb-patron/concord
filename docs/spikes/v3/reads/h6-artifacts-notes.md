## Page-by-page notes

Each quote is a short verbatim locator; the cited heading or table identifies its location. The implication describes what that page contributes to Concord's hosting assessment.

### Setup and API

- [Create a repo over REST](https://developers.cloudflare.com/artifacts/get-started/rest-api/) — retrieved 2026-10-15 20:47:22 CDT; 785 words. Walks through namespace selection, a Cloudflare API token with Artifacts Read/Edit permissions, repo creation, retrieving its remote, then Git push and clone. Quote, “This endpoint returns repo metadata only” (`3. Get the repo URL again`). Repo tokens are separately minted for Git; the REST quickstart is metadata/provisioning, not a REST commit writer.
- [Create a repo from a Worker](https://developers.cloudflare.com/artifacts/get-started/workers/) — retrieved 2026-10-15 20:47:22 CDT; 1,356 words. Shows Wrangler binding setup, `env.ARTIFACTS.create()`, returning the remote and initial token, and regular Git push/clone. Quote, “authorize the caller before creating repos or returning write tokens” (`Write your Worker`). Concord could use a Worker as a broker, but the example's initial token is write-capable and must be protected/short-lived.
- [Errors](https://developers.cloudflare.com/artifacts/api/errors/) — retrieved 2026-10-15 20:47:22 CDT; 297 words. Lists API/binding errors including duplicate/missing repo, import/fork in progress, invalid input/name/TTL/URL, upstream unavailable and service memory limit. Quote, “The operation exceeds service memory limits” (`Error codes`, `MEMORY_LIMIT`). Async import/fork readiness and memory limits can surface as operational errors; the page gives no numeric memory budget.
- [Git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/) — retrieved 2026-10-15 20:47:22 CDT; 590 words. Documents smart HTTP clone/fetch/pull/push, repo tokens, and Git protocol support. Quote, “Push uses the standard v1 receive-pack flow” (`Protocol support`). Clone/fetch support v1 and v2; push supports v1 only, and optional v1 `filter`/`include-tag` capabilities are unsupported. Concord's Git clients must use protocol v1 for push and avoid those optional features.
- [REST API reference](https://developers.cloudflare.com/artifacts/api/rest-api/) — retrieved 2026-10-15 20:47:22 CDT; 1,747 words. Documents namespaces, repo create/list/get/delete/fork/import, read commit/tree/blob/file/raw, and token list/create/revoke routes. Quote, “Object routes use immutable Git SHA-1 hashes” (`Repo content`). REST offers detailed reads and control-plane mutations but documents no REST write endpoints for Git objects or refs; commits must go through Git push.
- [Workers binding reference](https://developers.cloudflare.com/artifacts/api/workers-binding/) — retrieved 2026-10-15 20:47:23 CDT; 1,983 words. Describes namespace methods `create`, `get`, `list`, `import`, `delete`; repository capability methods for info, token management, fork, log, commit/tree/blob/file reads. Quote, “The Artifacts binding returns disposable repository capabilities” (intro). The binding supports management and inspection, not direct commit/tree/blob/ref writes; use Git protocol or a Git library to write. `log()` follows first-parent only and caps at 1,000 entries.
- [Wrangler commands](https://developers.cloudflare.com/artifacts/api/wrangler/) — retrieved 2026-10-15 20:47:23 CDT; 1,261 words. Documents listing/getting namespaces, creating/listing/getting/deleting repos and issuing repo tokens. Quote, “Issue a repo-scoped Artifacts token” (`artifacts repos issue-token`). Wrangler is a CLI for administration and token issuance, not a documented Git object authoring API.

### Data model and recommendations

- [Best practices](https://developers.cloudflare.com/artifacts/concepts/best-practices/) — retrieved 2026-10-15 20:47:23 CDT; 1,069 words. Recommends repos per agent/session/application, unique identifiers, forking stable baselines, least-privilege short-lived tokens, git notes for harness metadata, and namespace partitioning. Quote, “If you have `10,000` agents, create `10,000` repos” (`Create a repo per agent, session, or application`). This is directly aligned with isolated candidate repositories; the same page warns against a shared hot repo and says shard hot namespaces under request-rate limits.
- [How Artifacts works](https://developers.cloudflare.com/artifacts/concepts/how-artifacts-works/) — retrieved 2026-10-15 20:47:23 CDT; 455 words. A repo is an isolated Git service in a namespace; repo state includes history/refs, tokens, remote and lifecycle. Claims synchronous replication across multiple data centers and asynchronous copies to object storage/snapshots. Quote, “a repo is a single logical instance that Cloudflare can route to from any region” (`Core model`). Durable storage is stated, but no SLA, restore process or read-after-write guarantee is given.
- [Namespaces](https://developers.cloudflare.com/artifacts/concepts/namespaces/) — retrieved 2026-10-15 20:47:23 CDT; 412 words. Namespaces group repos by environment, tenant or shard; they can be implicit or explicitly created and can carry immutable `eu`/`us` jurisdiction. Quote, “You cannot change a namespace jurisdiction after creation” (`Choose a data location`). Concord must decide jurisdiction at namespace creation; the jurisdictions are not a list of individual regions.
- [Repositories](https://developers.cloudflare.com/artifacts/concepts/repositories/) — retrieved 2026-10-15 20:47:23 CDT; 651 words. Defines identity as namespace/name plus API repo ID, and separates binding/REST control plane from Git data plane. Quote, “The Git protocol is the data-plane interface” (`Understand how the interfaces relate`). This clearly maps a Concord repo to one Artifacts repo; metadata and authorization management remain separate from Git content operations.

Quote, “Each push still starts its own Workflow instance” (`Run one workflow for every repo in a namespace`). - [Data localization](https://developers.cloudflare.com/artifacts/guides/data-localization/) — retrieved 2026-10-15 20:47:24 CDT; 256 words. - [Event subscriptions](https://developers.cloudflare.com/artifacts/guides/event-subscriptions/) — retrieved 2026-10-15 20:47:24 CDT; 700 words. Lists repo create/delete/fork/import/push/clone/fetch and token create/revoke events, with repo/account source and event payload examples. - [Import repositories](https://developers.cloudflare.com/artifacts/guides/import-repositories/) — retrieved 2026-10-15 20:47:24 CDT; 469 words. Imports public HTTPS Git remotes through REST or binding, optionally selecting branch and shallow depth; import may continue after request returns. Quote, “An import can still be in progress after this request returns” (`Import a public HTTPS repo`). ## Answers for Concord v3

### 1. Data model: repos, objects, refs and history

An Artifacts namespace is a grouping and routing boundary. Namespace plus repo name is the stable address; the API also returns a repo ID. A repo is an isolated Git service with its own remote, refs/history, tokens, lifecycle and durable state. Git objects are identified/read as SHA-1 commit/tree/blob objects; REST and the binding expose read inspection. Git smart HTTP is the documented write path for commits, trees, blobs and ref updates: clients push ordinary Git history. The docs do not describe Cloudflare's physical object layout or a separate API for writing individual objects or refs. Repo `log()` reads first-parent history only (default 50, maximum 1,000); normal Git clients can inspect full history. [Repositories](https://developers.cloudflare.com/artifacts/concepts/repositories/), [How Artifacts works](https://developers.cloudflare.com/artifacts/concepts/how-artifacts-works/), [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/), [REST API](https://developers.cloudflare.com/artifacts/api/rest-api/), [Git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/).

### 2. All documented write/read surfaces and authentication

- **Workers binding:** configure `artifacts` in Wrangler; deployed Worker accesses `env.ARTIFACTS` without passing a token. Binding namespace methods create/get/list/import/delete; repo handle methods manage metadata/tokens, fork, inspect commit/tree/blob/file and log. No direct binding method writes Git content or refs. For Worker-side writes, use a Git client/library such as isomorphic-git against the repo remote. Wrangler itself needs auth for local commands. [Authentication](https://developers.cloudflare.com/artifacts/guides/authentication/), [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/), [isomorphic-git](https://developers.cloudflare.com/artifacts/examples/isomorphic-git/).
- **REST API:** Cloudflare API token in `Authorization: Bearer`; Read permission for read routes and Edit for writes. It creates, lists, gets, forks, imports, deletes repos and manages repo tokens; reads log/commit/tree/blob/file/raw. The docs show no REST object/ref write method. Import guide/reference is for public HTTPS remotes; no private-source credential mechanism is documented. [REST API](https://developers.cloudflare.com/artifacts/api/rest-api/), [Authentication](https://developers.cloudflare.com/artifacts/guides/authentication/), [Import repositories](https://developers.cloudflare.com/artifacts/guides/import-repositories/).
- **Git smart HTTP:** standard remote `https://<ACCOUNT_ID>.artifacts.cloudflare.net/git/<namespace>/<repo>.git`; supports clone/fetch/pull/push. Repo-scoped token is Bearer header (recommended) or token secret in Basic-auth password slot. `read` allows clone/fetch/pull; `write` also allows push. Clone/fetch support protocol v1/v2; push only v1. [Git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/).

### 3. Limits, concurrency, consistency, durability and regions

Published numeric limits: 1 GB repository storage; 32 MB individual file/blob; 1 TB account storage (request increase); unlimited repos and namespaces; 2,000 control-plane requests per 10 seconds per namespace and 2,000 Git requests per 10 seconds per repo. No documented max push body, general request size, simultaneous connections/writers, request concurrency or operations-per-second guarantee beyond these windowed request rates. The service reports `MEMORY_LIMIT`, but no numeric threshold. No explicit read-after-write/linearizability guarantee, concurrent ref-update/conflict rules, or transaction behavior is documented. [Limits](https://developers.cloudflare.com/artifacts/platform/limits/), [Errors](https://developers.cloudflare.com/artifacts/api/errors/).

Cloudflare says it synchronously replicates repo data across multiple data centers, asynchronously copies to object storage and snapshots, and replicas do not incur storage charges. It gives no stated durability percentage/SLA, backup retention, restore procedure or customer-controlled backup facility in these pages. `eu` and `us` namespace jurisdictions restrict where data is stored and processed; unrestricted is the default. No individual region selection is described. [How Artifacts works](https://developers.cloudflare.com/artifacts/concepts/how-artifacts-works/), [Pricing](https://developers.cloudflare.com/artifacts/platform/pricing/), [Data localization](https://developers.cloudflare.com/artifacts/guides/data-localization/).

### 4. Pricing and operation counting

On Workers Paid, the published schedule is first 10,000 operations/month included, then $0.15 per additional 1,000; first 1 GB-month storage included, then $0.50 per additional GB-month. Billing is stated to start October 14, 2026. Storage is aggregate across repositories; daily peak storage is averaged over a 30-day billing period, replicas are not charged separately, and repos remain billable/stored until explicitly deleted. Workers Free is unavailable. The documentation names create, push, pull and clone as operation examples, but does **not document** exact event/metering units for a clone, fetch, a multi-ref push, a binding call/read, REST read, token call, fork, import, or delete. It does not state an egress charge or egress allowance. Analytics event counts are observability counts, not an explicit billing formula. [Pricing](https://developers.cloudflare.com/artifacts/platform/pricing/), [Metrics](https://developers.cloudflare.com/artifacts/observability/metrics/), [Changelog](https://developers.cloudflare.com/artifacts/platform/changelog/).

### 5. Forks, branches, import/export, backup and deletion

Fork creates an independent repo starting with source history; it can include only the default branch or all branches. Repos then diverge with separate tokens and lifecycle. Branches are supported through ordinary Git; best practices say use branches when collaborators share a lifecycle, and separate repos for autonomous units. Import supports public HTTPS Git source, branch and optional shallow depth. A normal Git clone/fetch/push is the documented export/transfer path; no dedicated export or backup/restore API is described. Delete is available via binding, REST (returns 202 Accepted) and Wrangler; pricing says stored repos persist until explicitly deleted. [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/), [REST API](https://developers.cloudflare.com/artifacts/api/rest-api/), [Best practices](https://developers.cloudflare.com/artifacts/concepts/best-practices/), [Import repositories](https://developers.cloudflare.com/artifacts/guides/import-repositories/), [Pricing](https://developers.cloudflare.com/artifacts/platform/pricing/).

### 6. Status, known limitations and changelog

Status is **open beta**, documented October 1, 2026, and available only to Workers Paid customers; billing began October 14, 2026. Not GA in the reviewed docs. Known protocol restrictions: push is v1 only; optional v1 `filter` and `include-tag` capabilities unsupported; binding history is first-parent and max 1,000 entries; storage/request limits above. Changelog documents the progression from private beta (April 16), Wrangler management (May 18), dashboard (June 17), jurisdiction (August 13), to open beta (October 1). [Changelog](https://developers.cloudflare.com/artifacts/platform/changelog/), [Git protocol](https://developers.cloudflare.com/artifacts/api/git-protocol/), [Workers binding](https://developers.cloudflare.com/artifacts/api/workers-binding/), [Limits](https://developers.cloudflare.com/artifacts/platform/limits/).

### 7. Many repos, concurrent writers and agents

Cloudflare explicitly recommends a repository per agent/session/task and says a 10,000-agent workload should create 10,000 repos; changelog marketing claims creation of tens of millions. The hard limits table says repository and namespace counts are unlimited, but account storage and request rates still bound deployment. Use unique repo names, stable-baseline forks, short-lived least-privilege tokens and split hot workloads across namespaces. Do not use one shared repo as a queue or hot spot. Docs do not specify safe same-repo concurrent writer counts, lock/CAS semantics, merge behavior or write throughput; branches are advised only for collaborators with a shared lifecycle. Thus documented architecture favors per-agent repos, with actual Concord-scale behavior and billing requiring workload measurement because no numeric concurrency guarantee or exact billing-unit map is published. [Best practices](https://developers.cloudflare.com/artifacts/concepts/best-practices/), [How Artifacts works](https://developers.cloudflare.com/artifacts/concepts/how-artifacts-works/), [Changelog](https://developers.cloudflare.com/artifacts/platform/changelog/), [Limits](https://developers.cloudflare.com/artifacts/platform/limits/).
