# Reservation model findings (Python implementation only)

## Lease unit
Reservations are rows scoped to a project and agent and store a project-workspace-relative `path_pattern` that may be a literal path, glob, or virtual namespace; the JSON audit artifact is stored under `file_reservations/<sha1(path)>.json`. The model fields are summarized in the prior S2b notes; the implementation and emitted artifact are in `app.py:3881-3927, 11442-11749`.

## Exclusive versus shared
An overlap conflicts only when at least one side is exclusive; shared/shared pairs and the same agent's own reservations are skipped (`app.py:4315-4345`). Virtual namespaces only conflict on exact matching virtual strings, not with filesystem paths. Tests cover shared/shared and exclusive/shared cases (`tests/test_file_reservation_lifecycle.py:253-411`).

## Advisory versus enforced
`file_reservation_paths` returns both grants and conflicts, so a conflicting code-path claim is still granted; its response warns that server-side exclusivity is advisory for code paths (`app.py:11442-11749`). Optional installed Git hooks can block staged commits and outgoing pushes by default, but advisory mode, `AGENT_MAIL_BYPASS`, missing hooks and Git's `--no-verify` make this local enforcement bypassable (`guard.py:268-712`). The tool comments describe separate server checks for Mail archive paths; do not conflate those with general code-path lease enforcement.

## Expiry and renewal
The tool's default TTL is 3600 seconds, but its body only warns below 60 seconds; despite the test title, that body does not enforce a 60-second minimum (`app.py:11442-11516`, `tests/test_file_reservation_lifecycle.py:1121-1151`). Renewal selects active/unexpired rows, extends from `max(now, current expiry)` by at least 60 seconds, and cannot revive expired rows (`app.py:12122-12255`, test lines 802-872). Release sets `released_ts`; artifact expiry is clamped to release time (`app.py:3881-3927, 11753-11896`).

## Conflict detection and pattern overlap
The reservation checker skips released rows, same-agent rows and shared/shared pairs, then applies exact virtual matching or filesystem pattern checks (`app.py:4315-4345`). `_patterns_overlap` cross-matches both normalized patterns using Git-wildmatch PathSpec, with symmetric `fnmatchcase`/equality fallback (`app.py:4366-4378`). The create path uses a union prefilter but deliberately sends globbed candidates through detailed symmetric matching to catch reverse-glob overlaps (#193; `app.py:4407-4463, 11442-11749`).

## What an agent sees on conflict
The MCP response contains the requested `granted` entries and `conflicts` with the requested path plus holder agent, held pattern, exclusivity and expiry; conflicts do not block the grant (`app.py:11442-11749`). The optional hook instead writes a diagnostic naming the changed path, matching pattern and holder, then exits nonzero in block mode (`guard.py:268-475, 476-712`).

## Stale lease cleanup
Reserve, renew and reservation-resource listing invoke cleanup. TTL-expired rows are marked released, then stale rows are evaluated using owner inactivity plus recent mail, filesystem and Git activity; orphaned owners are immediately stale, and records are rewritten to the Git archive (`app.py:3967-4135, 4221-4312, 11442-11749, 12122-12255, 13812-13893`). Force release uses those diagnostics and refuses while recent activity makes the reservation non-stale (`app.py:11906-12119`).

## Problems found in use
The changelog records naive/aware datetime failures in TTL transitions and an earlier omission of Git artifact updates on release/expiry (`CHANGELOG.md:241, 263`). Source comments and regression tests identify stale SQLite snapshots/phantom conflicts (#129/#130), orphan reservations after owner deletion (#161), DB rows left behind on archive failure (#180), reverse-glob false negatives (#193), same-agent macro auto-release (#196), and broad globs causing about 56,000 sequential Git forks per cleanup tick (#240; `app.py:1336-1406, 3967-4135, 4221-4312, 11442-11749`; test lines 802-872 and 1152-1193). The guard also documents Windows shebang dispatch and Husky custom-hook preservation failures (#262/#264; `guard.py:44-235`). Some tests remain permissive about overlap semantics and minimum TTL, so those cases provide weaker evidence than the non-revival and rollback regressions.
