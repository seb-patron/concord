## Sections
1. **Hardware** Requirements change by deployment size and workload, and GitLab can run on one node or be distributed across many. This page applies to the Free, Premium, and Ultimate GitLab Self-Managed editions.
2. **CPU** A single-node baseline is 8 vCPU, and ARM is supported. Burstable instances are discouraged because performance is inconsistent.
3. **Memory** A single node uses 16 GB as baseline, with 8 GB possible in constrained environments; swap should be disabled where possible. Distributed systems allocate memory by component and load.
4. **Storage** Single-node disk includes 40 GB for application/OS/logs/temp files, 5–12 GB for PostgreSQL, and repository storage at least as large as all repositories combined. SSD-backed storage is recommended, network file systems and burstable disks are discouraged, and binary assets can use object storage.
5. **Infrastructure** GitLab supports cloud providers and customer infrastructure if requirements are met. Underlying platform issues fall outside GitLab Support.
6. **Supported infrastructure** Common clouds include AWS, GCP, and Azure; Kubernetes is supported for cloud-native installations if it meets chart prerequisites. The page states no per-provider monthly infrastructure price.
7. **High availability** Synchronous replication requires under 5 ms between nodes, and availability zones should be odd in number for quorum. A single instance cannot span regions; GitLab Geo is the multi-region option.
8. **Component requirements** GitLab needs distinct database, cache/session, application, job, and storage components, with requirements varying by architecture. This is more operationally involved than a single-process server.
9. **PostgreSQL** PostgreSQL is the only supported database and may be bundled or externally managed. External instances have required settings and version constraints.
10. **Supported versions** GitLab 16.x through 19.x are paired with PostgreSQL minimum versions 13.6, 14.14, 16.5, and 17.x respectively, with the page listing maximum supported major versions too. Minor PostgreSQL updates should be current for bug and security fixes.
11. **Storage requirements** Most instances should allocate at least 5–10 GB to PostgreSQL and Ultimate at least 12 GB, including 1 GB vulnerability data. Storage scales with users and installed features.
12. **Extensions** The required and recommended PostgreSQL extensions include amcheck, btree_gist, pg_trgm, plpgsql, and pg_stat_statements, with minimum GitLab versions and databases specified. Some extension installation requires PostgreSQL superuser access.
13. **Gitaly Cluster (Praefect)** A Gitaly Cluster needs a dedicated PostgreSQL instance separate from GitLab’s main database. Full HA requires a third-party PostgreSQL solution.
14. **Redis or Valkey** Redis/Valkey stores user sessions and background tasks; Redis 7.2 or Valkey 7.2 are recommended, with minimum versions 7.0 and 7.2. Redis Cluster and serverless Redis/Valkey are unsupported.
15. **Puma** Puma settings depend on the deployment, and Linux package defaults are recommended. The docs link separate tuning guidance for workers and threads.
16. **Sidekiq** Each background-job process needs at least 200 MB and may grow significantly under load. Installations with over 10,000 users should allocate at least 1 GB per Sidekiq process.
17. **Object storage** Object storage is recommended for all installations and required when distributed; it holds LFS, CI artifacts, uploads, registry data, and backups. Any S3-compatible service is supported per the linked provider guidance.
18. **Optional components** Optional features add their own infrastructure requirements beyond core GitLab. They should be costed only when enabled.
19. **Container Registry** The registry requires a domain, TLS, and filesystem or S3-compatible storage, and can move to dedicated infrastructure for high traffic. It stores Docker/OCI images.
20. **GitLab Pages** Pages serves static project/group websites with a separate daemon and wildcard DNS; custom domains need an extra IP and TLS. This is an independent static asset hosting function.
21. **Elasticsearch and OpenSearch** Advanced search requires a separate cluster sized to indexed content volume. This adds compute, disk, and operational work.
22. **Prometheus** Prometheus monitoring is bundled with the Linux package and enabled by default. Operators can configure or disable it.
23. **Zoekt** Code search runs as a separate service and has its own resource requirements. It is optional to the core forge.
24. **ClickHouse** Product analytics requires a separate ClickHouse database service. This is another optional stateful component.
25. **AI Gateway** Duo AI features require a standalone Docker/Kubernetes service. The page links to a separate sizing guide.
26. **Secrets Manager** Secrets Manager is a Kubernetes service requiring its own PostgreSQL database and load balancer. It adds considerable platform prerequisites.
27. **Supported web browsers** GitLab targets widely available desktop and mobile versions of Firefox, Chrome, Chromium, Safari, and Edge. Running without JavaScript is unsupported.
