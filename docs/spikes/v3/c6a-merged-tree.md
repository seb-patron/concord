# What happened when the forty replay conflicts were merged

**Answer.** Ordinary Git left all forty sampled conflicts. A byte-prefix union limited to proven append-only text cleared four. Separately rebuilding the generated trail index and checking it cleared sixteen more. Twenty pairs therefore produced a conflict-free tree under one of those rules; twenty still had other unresolved paths. The rebuilt indexes passed the repository’s freshness validator. The full test suite did not finish, so these results show conflict resolution and index freshness, not that every resulting tree is correct.

This evidence informs the owner’s question about whether a structure-aware merge at landing can support shared writing, alongside the recorded [exclusive write claim](../../decisions.md#d-unit-1-exclusive) and [structure-aware landing merge](../../decisions.md#d-unit-4-struct-merge) decisions. It does not change either decision. The results are from historical pull-request revisions in one repository, not live concurrent work.

## Terms and evidence

A **replay** reruns Git’s merge calculation on saved branch-tip revisions. A **branch tip** is the saved commit at the end of one pull request. The **merge base** is the shared ancestor commit Git uses for a three-way merge. A **tree** is Git’s snapshot of files and contents. A **textual conflict** means Git could not combine a path automatically. **Unresolved paths** are files still marked unmerged in Git’s index, the staging database used during a merge. A clean tree means no unresolved paths; it does not mean tests passed or the content is semantically correct.

The input contains the forty conflict records from the earlier [SP-F5 larger lock-scheme replay](../../../spikes/v3/sp-f5/output.txt). The committed transcript below carries every pair name, merge base, both branch-tip revisions, and the ordinary merge-tree result identity, so reproduction does not depend on the old run’s temporary pair file. Its SHA-256 digest identifies the exact supplied input. The source checkout and its supplemental object mirror were read-only. The script accepts `--source` and `--supplemental-mirror` paths for another local checkout; it needs no network access.

The ordinary comparison uses the replay baseline command, `git merge-tree --write-tree --merge-base=BASE LEFT RIGHT`. It then checks a normal two-branch merge by starting at `LEFT`, merging `RIGHT` with Git’s `ort` strategy, and verifying Git computed the recorded base. This is a two-parent, three-way merge; it does not combine both tips as one octopus merge. A nonzero command, failed index inspection, inconsistent merge status, or failed tree write is reported as an operational failure, never as a successful merge.

The union rule was eligible only for `LAB_READING_TRAIL.md` when the actual base bytes were a prefix of both sides. That proves those particular versions retained the complete base and added bytes after it. `trail/INDEX.md` is generated output, and rewritten trail documents do not pass this content check. For the generated index, the replay separately ran `scripts/build_trail_index.py` when that generator was present and not itself conflicted, then ran `scripts/build_trail_index.py --check`. This follows the owner’s recorded decision to rebuild generated files at land when the checker can run ([decision D-UNIT-6-REGEN](../../decisions.md#d-unit-6-regen)). A union is not used as a substitute for regeneration.

A missing stage-one file means the two sides added a path with no recorded base version. Such a path is left unresolved by the byte-prefix rule. Git could apply a separately chosen empty ancestor, but this replay did not invent one. Mergiraf, a syntax-aware merge tool, was unavailable and was not installed.

The freshness validator reported `trail index: current` for all twenty-four attempted rebuilds. Three more historical pairs had a conflict in the generator itself, so Python could not run it; four earlier revisions did not yet contain the validator. The remaining twenty conflict pairs need a different resolution for at least one non-generated path, or for a generator conflict. These counts measure file-level resolution only.

The repository test command was run once on the first clean merged tree with `PYTHONPATH=tests/ci_support:src`, `TMPDIR` set to the delegated temporary directory, and bytecode writing disabled. It timed out after two minutes while still running lab-recovery tests; no complete test summary was produced. The process group was terminated. Later clean trees explicitly record that the full suite was not repeated; generated-index freshness checks continued for later pairs. This run therefore provides no green suite result and the incomplete test output is not evidence of merge breakage. Earlier retained summaries also varied: they record ten or eleven failures, forty-seven errors, and five or six skipped tests; one run also listed seven expected failures. The earlier claim of eleven failures on every run was inaccurate.

The transcript records the full pair list and revisions, result tree identities, unresolved paths, validator outcomes, and test-check state. Reproduce from the repository root with a local pair manifest and local source clone:

```sh
TMPDIR="$DELEGATE_SCRATCH_DIR" PYTHONDONTWRITEBYTECODE=1 \
  python3 spikes/v3/c6a/merged_tree.py /path/to/pair-results.json \
  --source /path/to/gen-v-research-tools \
  --supplemental-mirror /path/to/local-object-mirror
```
