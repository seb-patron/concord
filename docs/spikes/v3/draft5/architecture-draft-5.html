Concord v3 Architecture

Concord v3 is an agent-first forge for our own projects. An agent sends a change; Concord holds the issue, checks the exact prospective result, and alone moves the canonical Git branch. This draft records what is chosen, measured, proposed and still unknown.

1Plain summary

DECIDED Concord v3 continues as a design and build project for our repositories. GitHub carries current work until v3 is ready, then one or two projects may trial v3. The owner wants the plans updated before the roadmap or further build runs. The contest no longer determines the schedule. These are the 17 October continue-building and plans-first decisions (D-V3-CONTINUE-BUILD, D-UPDATE-PLANS-FIRST).

DECIDED v3 is an agent-first forge: issues express work, agents create revisions through a common application programming interface (API), command-line interface (CLI) or Model Context Protocol (MCP) tools, and the service alone advances canonical main. People plan, review, cancel and steer. A one-way GitHub mirror makes selected Git refs discoverable. The own-forge and no-GitHub-work decisions are dated 12–16 October (D-V3-OWN-AGENT-FORGE, D-NO-GITHUB-WORK).

TO TEST Scion makes publication cheap and uses an optimistic pre-deploy/post-merge path at the scale of a roughly 100 GB monorepo and tens of millions of daily checkouts. Gas Town assigns durable work through Beads but sends conflicts to one serial merging agent. Concord tries a third point for smaller agent projects: one issue work slot, exclusive but fine-grained file or symbol writing claims, nonblocking reviewed revisions, and short ordered ref moves. The matched replay benchmark and current-agent trial will compare its overhead with both optimism and coarse serialization. Scion's and Gas Town's workloads do not prove Concord's result.

MEASURED STRUCTURAL; 16 Oct 2026. The 16 October symbol replay found 21 cleanly merging pairs freed from 241 file-blocked pairs, or 8.7%, among 1,304 overlapping final-revision pairs; no observed textual conflict passed its symbol gate. This is a modest structural gain in that historical cohort, not measured minutes saved or semantic compatibility. The merged-tree study resolved 20 of 40 textual conflicts with narrow append-only union or generated-index rebuilding, but a full suite did not finish. Sources: Symbol claims on overlapping pull requests and What happened when the forty replay conflicts were merged.

ASSUMED Since draft 4, the claim default is corrected to the owner's exclusive rule; issue custody, fenced turns and queue previews are described as designs under test; exact revision review replaces approval carry-forward; force land has only its narrow approved bypass; and hosting starts from v2 Cloudflare rather than an unselected large VPS. The assumption is that a coherent document is useful before a production host or claim-timing choice; the owner explicitly asked for this order on 17 October.

TO TEST The most consequential uncertainties are whether verified symbol keys save meaningful waiting after check failures and repair cost, whether automatic wait-line handover can revalidate authority atomically, whether preview-based child work pays for invalidation, whether Artifacts can enforce promoter fencing, and which pre/post-land check policy keeps main healthy at acceptable cost. Sections 15–16 name the tests and decisions.

2How to read the labels

DECIDED means an active owner instruction, with its plain meaning and date. The parenthesized decision ID is a lookup key, not the explanation. A decision may govern the design without the feature being live in v2. The supplied 17 October decision status snapshot is the authority for that distinction.

MEASURED means an observed result at a stated scope, with its number and report. A local Git replay is evidence about its selected historical commits, not live service throughput. An account screenshot is an observation for its filtered rows, not a whole invoice. Estimates are stated separately.

TO TEST means a named experiment or acceptance test can settle the choice. It never means approval to spend money or move a project. ASSUMED means a proposed implementation detail with a reason but no confirming measurement. Every mechanism below also says where its idea came from. STRUCTURAL findings concern protocol or source properties; CAPABILITY-DEPENDENT findings depend on dated agent or platform behavior and need retesting.

ASSUMED Several paragraphs contain a fixed invariant plus an unselected way to implement it. The label next to each paragraph applies to its operative claim; a table row gets its own label. Where a design mixes them, the sentence names the decision separately and identifies the implementation as a proposal. Dates refer to the source or observation, not today's vendor guarantee.

3Goals and non-goals

DECIDED Own projects first, with agents as the primary clients and people as supervisors. GitHub remains the working forge until v3 is ready; afterward, Concord mirrors selected refs outward in one direction and can let a pilot project return to GitHub. The owner chose this on 17 October (D-V3-CONTINUE-BUILD) and previously chose an own agent forge and no routine GitHub work (D-V3-OWN-AGENT-FORGE, D-NO-GITHUB-WORK). A narrow earlier GitHub exception for broken landing is historical, not the future product workflow.

DECIDED A hosted service for outside customers, selling, billing and a license choice wait until after the minimum viable product (MVP), by the 15 October hosted-service-later decision (D-HOSTED-SERVICE-LATER). Eventual self-host distribution still needs the owner-approved agent-driven installation path (D-DEPLOY-FLOW). No MIT promise appears here. Git Large File Storage is withdrawn as an MVP factor; the ten checked local repositories use none.

DECIDED Judge v3 by coordination cost on the same issues, not current GitHub merges per day. The owner ruled out that calendar baseline on 17 October because the full pipeline is absent and projects are in harder phases (D-NO-MERGES-PER-DAY). Measure duplicate-agent minutes, time waiting on code or issue custody, rework caused by another change, stale or conflicting sends, checks, reversions and human interventions per issue. Do not substitute a high land count for correctness or a low waiting count for less total work.

TO TEST The replay benchmark, the composed-code check of symbol-freed pairs, hosted promotion safety test, shadow mode and project-swap trial define MVP evidence. Each has a specified location and cost in section 15. A one-week app trial is a prospective acceptance test, not a claim that v3 is already more effective.

ASSUMED Worked example: an agent claims a task to repair a parser. The issue slot identifies that task and actor epoch one. It declares a symbol inside a source file and receives code fence seven. Its change gains revision one when sent; code fence seven stops excluding other writers, while the server holds the issue slot and exact revision authorization. Review finds a bug. The server revokes revision one, offers repair, and a second actor takes epoch two with a fresh code fence. Revision two gets its own checks and review. If the first actor sends after transfer, its old epoch is refused; if the owner closes the issue, both pending authorizations are revoked. This example is a protocol design, tested by the custody fault matrix, not an observation of a running v3 service.

6Issue custody lifecycle

DECIDED An ordinary issue must not silently receive two independent workers; the owner stated this on 16 October in the issue-claim redesign (D-ISSUE-CLAIM-REDESIGN). A declared contest is the sole exception, and its mechanics are deliberately outside this draft. Issue custody is separate from code units (files or symbols). A linked change or visible assignee by itself does not enforce one worker through review and repair.

TO TEST The proposed state machine is Open → Claimed → Sent → In review → Waiting to land → Landed → Closed. Inspection or review failure enters Needs repair; a new authenticated repair actor takes a new epoch and fresh code leases. Server-phase expiry enters Intervention, where no write or land authority is valid; an expired actor turn returns the task to Open. The local custody prototype must assert each transition, replay its events, and reject every late actor/result. The server holds the issue slot while no actor writes, so a repair does not create a duplicate task.

TO TEST Owner cancel and close are valid from Open, Claimed, Sent, In review, Needs repair, Waiting to land, Intervention and an explicitly declared Contest, as shown above. Contest's multiple-actor mechanics remain outside this draft. These actions atomically raise issue and code fences, invalidate authorization, wait requests and preview tickets, and log a reason. Cancel returns a still-open task to Open. Close enters Closed. A landed commit cannot be erased by cancel: a later request is a separate revert or repair. Reopen creates a new issue generation. The custody fault test must race cancel against send, review completion and the conditional ref update.

ASSUMED Prototype limits from the 16 October claims design: five-minute actor and code terms renewed in a batch every 100 seconds; ten minutes without productive action ends a hung turn even if heartbeats continue; inspection 45 minutes, review 60, queue 45, repair offer 30 and Intervention 15. Every value is owner-adjustable, a scenario input rather than production policy. An owner can extend a named phase before expiry with a reason and finite new deadline. A heartbeat alone never extends server custody. The owner has left the maximum claim age open (D-LEASE-MAX-AGE-OPEN, 16 October); a production cap requires replayed wait/abandonment evidence and an explicit owner choice.

TO TEST Issue edits increment a version. Before send, the actor acknowledges changed scope and grows code claims if needed. After send, a material issue edit invalidates inspection, review and queue results, requiring a new acknowledged revision. Ready-set dispatch also checks blocker edges, existing slot, active task, selection version and budget capacity; close releases dependent work only under the chosen post-land completion rule. Reopen and dependency edits must be replayed in the swarm fixture. The 15 October swarm study had only one open issue and no dependency edges in its available Concord backlog, so the draft-4 multi-backlog round claims are not evidence.

7Code claims

DECIDED Code-unit writing claims remain exclusive at file or symbol size, by the 14 October exclusive-unit decision and 16 October issue redesign (D-UNIT-1-EXCLUSIVE, D-ISSUE-CLAIM-REDESIGN). Shared or advisory writing is an evaluation arm, not the default. Presence is a separate signal with no write authority. A file lease overlaps every symbol in the file; parent and child symbols overlap; disjoint verified symbols can proceed. The server checks the current fence on publish, rather than trusting client-side convention.

MEASURED STRUCTURAL; 16 Oct 2026. The repaired 16 October finder used tree-sitter 0.25.2 and tree-sitter-language-pack 0.13.0, with language-specific queries through one engine. It freed 21 of 241 file-blocked historical pairs and let through zero of 40 textual conflicts in the selected 1,304-pair sample. It widened 1,651 of 3,931 changed regions on shared paths to files (42.0%); Bash parser errors dominate that fallback. The old 155,253 fallback events are from another population, and the claimed old matched-cohort rate is withdrawn. Symbol claims on overlapping pull requests reports these counts. This is a final-diff proxy, not a human-labelled stable identity test.

TO TEST Pin the grammar, parser and query versions in each policy. A key includes repository, normalized path, enclosing and own names, node kind and policy version. Compare old and new changed sides; added files use the new side, deletions the old, and a rename claims both old and new names. Insertions between units claim only the changed side; the symbol report sentence saying they always widen to file was corrected by its final review. Widen to file on parse error, unsupported or binary format, ambiguous same-line siblings, spanning hunk, moved or renamed path without a reliable alias, generated output, and uncertain boundary. The unit-identity fixture and human-labelled sample decide whether any key is safe for enforcement. Do not use Git funcname as an authority key merely because it produces readable hunk headings.

DECIDED Declare initial expected units, request growth when discovery changes scope, then verify the exact diff before first publication (D-LEASE-Q5-CPLUS). Forecast units on an issue are planning hints, not mandatory atomic issue-plus-code acquisition; the owner rejected that as the leading framing on 16 October. The server grants all units of one code request or none, checks overlap under a pinned policy and reconciles the actual changed side before publication. A repair turn takes new leases for its full replacement footprint, even where content did not change since the preceding attempt.

MEASURED CAPABILITY-DEPENDENT; 16 Oct 2026; re-test with current agents. The 16 October spec-prediction study froze 9,795 eligible records. Among 4,030 diffable completed implementations, 5,428 of 21,554 validated declared file entries were unchanged (25.2%); 89 of 326 linked families with an observed first implementation later declared another file. A refused-scope state alone does not prove an omitted file: the published classifier marks 15 of 1,325 such runs as clean omitted-file diagnostics, and final review found an additional overlooked omission, so that count is provisional. The earlier “about 13% refused for scope” claim is withdrawn. These are code-aware specifications, not blind issue forecasts or observed mid-run lease grows. Sources: Spec prediction and its final review.

DECIDED An exclusive refusal enters a fair wait line automatically, with holder and advisory expiry, unless the request opts out; human-only controls may pause, move to front or force-release, with an audit event (D-LEASE-QUEUE-AUTO, D-LEASE-WAIT-LINE). A wait entry is not a grant. The next holder must receive a fresh fence and current authorization. A dead or revoked waiter cannot inherit the old queued credential.

TO TEST Automatic handover is allowed only if principal access, issue actor, change state, all requested units and the new fence are checked in one serialized transition. If that cannot be guaranteed across the deployed identity store, offer a short priority turn and require a new authenticated claim. The wait-line fault fixture settles which path is safe. Queue order includes multi-unit wait dependencies; detect cycles, refuse or revoke the youngest request deterministically, and preserve its original wait age when requeued. A prototype five-minute wait deadline and 45-second priority turn are adjustable scenarios, not settled service levels. Owner cancellation must invalidate both holds and waits immediately at the next serialized decision.

8Changes, revisions and review

DECIDED A change is a server object with successive immutable revisions, not a pull request. A repair republishes under the same change, but an earlier review never approves a new head by “unchanged files” carry-forward. The owner chose new-head review for repairs on 13 October (D-CHANGE-REVISIONS). A review record binds revision commit, tree, footprint, issue version, policy version and reviewer identity; queue admission checks that digest again. This lets a new writer start after first publication without granting an old revision permanent authority.

TO TEST The inspection and review state machine requires an eligible independent reviewer, a current exact revision, current issue acknowledgement and a passing required checker result. A changed revision, generated output, transformed child or changed queue candidate invalidates the relevant old evidence. Reviewers use the worker validation log and checker pass and run focused tests as needed, rather than repeating the full suite, following the 13 October reviewer policy (D-REVIEWERS-NO-SUITE). The exact review manifest and stale-verdict fixture are protocol tests; they do not prove human judgment quality.

DECIDED People can apply human review and define path rules, while agents remain the change authors. The 14 October human-controls decision (D-AGENT-FIRST-HUMAN-CONTROLS) authorizes configurable rules but explicitly leaves UI path human-approval rules unconfigured for this repository. Protection has agent-allowed, human-approval and human-only modes. A human-only path cannot be edited by an agent merely because an agent reviewer approves it.

TO TEST The draft-4 matrix “docs need none, normal code one agent, sensitive code owner” is not approved policy. Compare a minimum independent review, path-dependent human review and risk-based review using seeded findings and actual repair outcomes. Decide which severity blocks and when an advisory finding can defer work. The present design records severity, provenance and reviewer eligibility but does not claim every advisory finding is harmless. A review quality trial, not Scion's approval concept, selects defaults.

ASSUMED Keep conflict output as durable change data: base, both sides, structured Git conflict paths and the attempted resolver output. Jujutsu shows conflicts can be first-class data and Mergiraf supplies a syntax-aware optional resolver; Concord's Git mirror still receives ordinary resolved commits. If a sandboxed structure merge is enabled, fall back to Git line merge on parser error or unsupported content and run the full suite on the resulting merged tree, per the 14 October structure-merge decision (D-UNIT-4-STRUCT-MERGE). The forty-pair study's clean trees do not settle a general semantic merge policy.

9Landing

DECIDED Only a trusted hosted promoter moves canonical main; no agent gets its canonical write credential (D-NO-LOCAL-PROMOTER, 16 October). This is a short serialized ref decision, not a repository-wide edit lock. Immutable object construction, independent inspection and prospective checks may overlap. Competing successful moves of one main ref still form one ordered history. A local 15 October Git prototype landed eleven of twenty parallel changes and identified nine textual conflicts, with 73 and 118 retry attempts in its two fixtures; that demonstrates plumbing, not production throughput.

TO TEST For a local bare Git store, the promoter composes git merge-tree --write-tree MAIN REVISION, distinguishes clean/conflicted/operational-error output, then creates a commit with git commit-tree TREE -p MAIN -p REVISION under a pinned identity and message policy. After exact-candidate checks, git update-ref refs/heads/main NEW OLD conditionally moves the ref. Artifacts remote pushes are a separate implementation and must prove equivalent expected-old-ref and fencing behavior at the endpoint. A changed OLD means rebuild from the new main, rerun affected checks and reject stale results. Bound attempts, for example three in the prototype, then surface contention rather than spin.

TO TEST Before any conditional move, durably record a landing intent: repository, old and new commit IDs, exact tree and revision, issue and code authority versions, check and review digests, queue prefix, promoter fence and attempt number. Serialize owner cancel and the final authority check with the ref decision. After an uncertain push acknowledgment or crash, read main: NEW means reconcile completion, OLD means revalidate or abort, and any third ID quarantines the sequence for a person. Never announce land merely because the request was sent. The restart test injects crashes before compare-and-swap, after it and before completion recording. A later cancellation requests a new revert or repair; it cannot retroactively undo a completed move.

TO TEST A queue entry can receive a preview ticket for main plus an exact reviewed prefix. This borrows Zuul/GitHub queue speculation. Concord's added proposal lets another agent start a separate child change against that immutable preview commit. The ticket records predecessor revision IDs, prefix commit/tree, queue epoch and expiry. At file level, the child sees the entire prospective file; at symbol level it can request a verified disjoint symbol after the predecessor's writing lease ends. It still needs its own issue slot, code claims, checks and review. The preview-off benchmark arm measures whether avoided rebases exceed repeated prefix builds, invalidations and check work.

TO TEST Failure, replacement, ejection or owner bump of a predecessor increments the queue epoch and invalidates every descendant ticket and result. Stop a writing child by revoking its actor/code fences; revoke a published child's landing authorization. To preserve only the child's delta, record original parent P and child C, then transplant P..C onto the new valid prefix N with an explicit-base three-way merge such as git merge-tree --write-tree --merge-base=P N C; create a new child revision with N as parent. A clean textual result is still an untrusted draft until it has fresh unit derivation, writing authority, exact-tree checks and independent review. Equal tree IDs do not make different parent commits equivalent. The queue fault test covers both changed predecessor and unchanged landing with changed ancestry.

DECIDED Owner force-land is narrow: an already approved change must rebase cleanly; the owner token skips only stack validation and creates a forced-queue event and “Forced by owner” badge. It does not skip review, clean rebase, required non-stack safety checks or the server-only main rule (D-FORCE-LAND, 14 October). If an in-flight candidate differs, it must be rebuilt and rechecked under the same authorization rules. The forced-path fixture checks this scope.

DECIDED Generated outputs are rebuilt at land when the generator can run in the checker; exclusive output leases are the fallback when it cannot (D-UNIT-6-REGEN, 14 October). The forty-pair study found sixteen conflicts cleared by generated-index rebuilding and four by narrow byte-prefix append union, with a freshness validator on rebuilt indexes; the full suite did not finish. Generated files are not all automatically “unmergeable,” and a clean index does not validate the rest of a program.

TO TEST Default pre-land gate, batch size, post-land full suite and red-main policy remain open. Options are full required checks before each CAS, tiered fast checks before each CAS plus a batch-tip suite, or a more optimistic pre-deploy/post-merge approach. Bors and SubmitQueue show why individual revision checks do not validate combinations; Scion shows the high-throughput optimistic alternative at different scale. If a post-land suite fails, pause later affected landings, retain the failed batch and exact checks, then use a measured bisect/revert procedure under owner policy. The local three-probe synthetic bisect is not proof that automatic rollback is safe with dependent changes or flaky checks. Issue close and dependent release should wait until the selected completion gate, keeping Landed distinct from Closed.

10Checks and runners

DECIDED The 14 October post-submission direction is push updates over WebSockets to checkers/promoters and the UI (D-PUSH-AFTER-SUBMISSION). Jobs must be pushed to authenticated isolated hosted runners in v3, with no promoter credential or canonical write token. An isolated checkout or container reads a specific prospective commit and receives a versioned check recipe. The check result names commit, tree, current main, queue epoch, policy version, recipe digest, runner and attempt. Transport push is a direction; the precise trust protocol is still a design and test item.

TO TEST A runner accepts a job with an attempt ID and deadline, executes it once or returns an idempotent prior result, bounds logs, and reports PASS, FAIL or UNAVAILABLE_ENV. FAIL is a candidate check's nonzero result in a valid environment; UNAVAILABLE_ENV means absent command, dependency, permission, toolchain or timeout prevents a meaningful judgment. Unavailable is never silently counted as pass. The prototype contract's 120-second per-command cap is a local scenario, not a service default. Build outputs go in a disposable overlay so the tested source identity remains fixed; a rewrite of tracked source requires a new candidate and review.

TO TEST The scheduler rejects a late or duplicated result if attempt, exact tree, current main or ticket changed. On a main compare-and-swap miss, it cannot reuse a pass for a different merged tree merely because the original revision passed. A replacement revision or preview invalidation also invalidates its earlier approval and check records. The integration fixture races old and new runner responses, crash/retry and policy edits, and asserts zero stale-result landings. A scripted checker oracle may prove this protocol; it does not constitute independent semantic review.

ASSUMED Separate a cheap per-candidate tier from broader end-to-end tests as a candidate policy because the owner approved running end-to-end work less often (D-E2E-LESS-OFTEN) and v2's full suite serialized many checks. The precise gate and batch membership remain section-16 decisions. Measure CPU time, workspace, transfer, failed checks and latency on representative jobs before setting runner count. A single Mac runner is excluded by the hosted-MVP direction; no speculative cloud container is claimed to fit 22 concurrent full clones simply because historical process intervals overlapped.

TO TEST Hosting recommendation from the 16 October study: keep Worker ingress, repository Durable Object coordination, Artifacts canonical Git and Workers Builds initially; evaluate a Cloudflare Container for trusted Git promotion and isolated checks.
