## Scope and terms

This audits the v2 files at observed `origin/main` c9d9278; the local `main` ref in this checkout is older, so the observed remote-tracking head and this worktree are the useful v2 baseline. A **code claim** is temporary exclusive permission to edit a file or verified symbol. An **issue work slot** is the server-held record saying who is working on one ordinary task, including review and repair periods. A **fence** is a generation number that makes a former holder's late action invalid. An **actor epoch** is the issue writing-turn generation; it advances when responsibility transfers to another run. An **issue generation** advances when a closed issue is reopened, so old work cannot regain authority. A **queue epoch** advances when the ordered queue or a predecessor changes enough to invalidate a preview. **FIFO** means first eligible overlapping wait request in, first served. A Git **object ID (OID)** identifies exact stored content or a commit. An **idempotency key** identifies one mutation attempt so an identical retry does not perform it twice. A **preview commit** is an immutable proposed version of a queued prefix that a child change can use as its parent. A **replay cursor** is the last durable event sequence the browser has applied. A **landing intent** is the durable record of a proposed movement of canonical `main`, reconciled with Git after a crash. These meanings come from the 16 October claims design and hosting study, which supersede the partly stale architecture draft. The five-minute renewable writing claim, exclusive units and nonblocking holds after first publication remain current owner policy (exclusive units, `D-UNIT-1-EXCLUSIVE`; lease extension, `D-LEASE-5MIN-EXTEND`; publication transition, `D-LEASE-BOTTLENECK-ASAP`). An exact maximum age for server-held issue custody is open (maximum age, `D-LEASE-MAX-AGE-OPEN`).

The v2 UI is not a generic forge frontend. It trusts one versioned repository snapshot with projections for changes, issues, leases, queue, jobs, findings and settings (`web/app.js:80-86`; `web/views.js:95-129`). V3 needs an issue slot, actor epoch, phase deadline, wait requests, preview tickets, dependency edges, check availability and landing intent in those projections or their replacements. Server authority remains decisive; browser role gates only hide inappropriate controls. **STRUCTURAL finding (17 October 2026):** do not make a button's visibility the access check (`web/api.js:328-341`; `src/auth.ts:122-146`).

## Live updates and consistency

**STRUCTURAL finding (17 October 2026):** today's browser is primarily refresh-on-action, focus and visibility, not a continuous 15-second data poll. Initial `loadRepo` fetches snapshot and one event page (`web/app.js:271-292`). `poll` asks for `/events?after=state.seq`, appends a page, then re-fetches the snapshot only if the returned version advanced (`web/app.js:328-359`). It runs after manual refresh (`web/app.js:1069`), when the tab regains focus or visibility (`web/app.js:1103-1111`), and after mutations (`web/app.js:950-969`); the one-minute anonymous poll guard applies only when `force` is false (`web/app.js:332-335`). Manual Refresh, fleet navigation and focus/visibility use `force=true` and bypass that guard (`web/app.js:1069,1091,1103-1111`); focus/visibility has its own five-second lifecycle guard. Credentialless repository reads also pass the separate shared request budget (`web/app.js:41-49`; `web/api.js:104-105`). The 15-second interval changes only the “Updated” label (`web/app.js:1112`), which is easy to mistake for live data refresh. The API cache uses an entity tag and can reuse an in-flight snapshot (`web/api.js:207-226`). It does not use a WebSocket or `EventSource`.

V3 should open an authorized event connection after a versioned snapshot, then apply numbered events in order from the saved cursor. On reconnect it requests all events after that cursor; if replay is incomplete, the version jumps, or the stream says the cursor is too old, it fetches a fresh snapshot and resumes from that snapshot's event sequence. A snapshot and stream subscription need a race-safe handshake: subscribe from the snapshot cursor, deduplicate repeated sequences, and do not show a later projection with an older authority version. Keep the existing manual refresh and focus resync as recovery paths. The browser must say “disconnected” and “state may be stale”; it must disable authority-sensitive actions until a fresh snapshot confirms actor/fence, review and queue ticket. Store a nonsecret cursor only if persistence is desired; the bearer token remains in memory. **CAPABILITY-DEPENDENT finding (hosting study, 16 October):** hibernatable WebSockets are a candidate, but hosted idle cost, replay retention and authentication ordering need measurement. The transport could change; the cursor and resync rules cannot.

## Hosting-independent core, hosting-dependent edges

**STRUCTURAL finding (claims and hosting designs, 16 October 2026):** keep the source-control concepts regardless of provider: one server-controlled canonical `main`; immutable changes; issue custody and actor fences; exclusive code claims with conservative file/symbol overlap; wait order; revision-bound review; exact merged-tree checks; conditional preview dependencies; numbered events and replay; durable land intent, readback and crash reconciliation; and an idempotent ref compare-and-swap.
