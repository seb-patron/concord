# Concord v3 platform audit against research and owner decisions

## Plain summary and answer

**The draft needs repair before it can guide hosting.** Its agent-first forge and one-way GitHub mirror match owner decisions. The host, runtime, Git storage, costs and migration schedule remain proposals. The October 16 owner direction starts the comparison from the live v2 Cloudflare arrangement, moves canonical promotion off the owner's machines, and sizes a small minimum viable product (MVP) host. Owner-machine promotion is excluded. A service for outside customers and a license choice wait until after MVP. The ten checked local repositories are below the documented Artifacts repository ceiling and none uses Git Large File Storage (LFS), so LFS import is optional, not an MVP service requirement (owner decisions and status, October 15–16; repository size check, October 15).

This audit covers the draft's platform sections and their cross-cutting statements. A separate audit covers claims, issues, landing, runs, checks and review. Consequently, a reference here to an exclusive code-unit claim, runner isolation or the temporary GitHub path identifies a platform dependency, not a redesign of those subjects. **STRUCTURAL** means a durable design, protocol or owner-policy mismatch. **CAPABILITY-DEPENDENT** means the finding depends on current product or agent capability and should be retested. All observations below are from supplied files dated October 15–16, 2026 unless a row says otherwise; vendor prices and limits are snapshots, not current guarantees.

Terms used below: a *forge* hosts Git code and development work; a *Worker* handles Cloudflare web requests; a *Durable Object* is its stateful component; *Artifacts* is Cloudflare's Git repository service. A *checker* tests a proposed change; a *promoter* moves the canonical, or authoritative, Git branch after checks. A *ref* points to a Git branch or tag; *compare-and-swap* (CAS) moves it only when its old value matches. A *code-unit claim* reserves a file or symbol for work; an *issue claim* records who is doing a task. A *runner* executes checks; *isolation* keeps its untrusted job away from server secrets. *HTTP* is the web request protocol; *MCP* is Model Context Protocol for agent tools; *WebSocket* is a two-way persistent connection; *SSE* is server-sent events, a one-way HTTP stream. A GitHub *mirror* copies selected refs outward and cannot restore Concord's database. October 15 research recommendations are not owner approvals.

More reading terms: a *virtual private server* (VPS) or *virtual machine* (VM) is rented computing capacity; a *tenant* is one owning account. A *repository actor* is its single coordination process. A Git *blob* holds file content; *immutable* content does not change after creation; a *bookmark* is another name for a movable ref; *derivation* computes an indexed view from stored facts. A *refspec* selects Git refs for transfer. A *cursor* marks the last event read; the *replay horizon* is how far back the service can resend events. *Atomicity* means related state changes appear together; *idempotent reconciliation* safely completes an interrupted operation on retry. *Pagination* splits a long result into bounded pages. An HTTP *Origin* names the site that initiated a request. *OAuth* is delegated sign-in; Cloudflare *Access* is its identity gate; a *principal* is an authenticated person or agent. *SQLite* is the embedded database. *API* means an application programming interface; *CLI* is a command-line interface. *Bun* and *Node* are server runtimes; a *Container* is a temporary isolated workspace. A *cutover* changes the source of truth. *Revocation* removes access. A *Git pack* is compressed transferred history. *CPU* means processor work. *VAT* is value-added tax; *IPv4* is an internet address type; *CPX42* is a named rented-server size. A *proxy* relays traffic; *retention* is how long data remains.

## Research with no clear home in the draft

**Current-state baseline and metering.** The live system uses a Cloudflare Worker, tenant and repository Durable Objects, Artifacts canonical Git and task copies, with Git traffic direct to Artifacts and a local checker/promoter. Workers Builds deploys from Artifacts canonical main (Workers Builds deployment decision, D-DEPLOY-WORKERS-BUILDS, active October 16). Replacing Artifacts therefore needs a replacement deployment source and a proven transition before removal. The October 12–15 account totals are aggregate and omit billable Artifacts operation counts. The owner's October 15 **filtered Billable usage screenshot**, not an invoice, establishes Workers Paid inclusions; Artifacts rows are absent. The read-only token cannot read subscription details. This account has no Cloudflare zones and currently serves the application on workers.dev, so a hypothetical proxied-zone request limit does not describe today's topology (Our measured usage; How Concord v2 uses Cloudflare today; Our Cloudflare account, October 15).

**Git placement and correctness.** Four candidates remain: Artifacts canonical with hosted Git computation, Artifacts for temporary task copies only, hosted server Git with SQLite, and Cloudflare Durable Object metadata and authoritative refs with R2 (Cloudflare object storage) and disposable Container computation. Artifacts' binding cannot directly move refs; Git push can, but expected-old-ref rejection, readback and crash recovery are unproved. Repository-scoped Artifacts write tokens must never give agents direct canonical write access. Use an enforcing gateway or isolated task repository for Git submissions in every candidate. For the Cloudflare-only candidate, authoritative Git objects must survive in R2 and refs and metadata in Durable Object storage after Container workspace loss; Container disk is temporary. A Cloudflare-primary deployment needs a versioned backup outside the Cloudflare provider/account failure domain, covering Git data, refs and consistent metadata. Artifacts' documented ceilings are one gigabyte per repository and 32 megabytes per blob. All ten local repositories checked on October 15 fit the repository ceiling; the largest held 120 MB Git data, and none uses LFS. One oversized blob was on a non-main branch. The earlier 542 MB directory figure is superseded by 140 MB. These are local-copy observations: one clone is stale, remote size and later growth were not measured. No private inventory belongs in a public hosting report (Cloudflare Artifacts documentation study; Concord v3 on our current Cloudflare setup; Repository size check, October 15–16).

**Recovery, protocol and operating limits.** A one-way GitHub mirror restores selected Git refs only. Independent backup needs Git objects and refs, database state consistent with those refs, identities and secrets, plus a tested restore. If LFS is later chosen, add a separately authenticated upload/download endpoint, content storage, checksums and restore; its generic draft checklist is not an MVP commitment. *Git smart HTTP* means clone, fetch and push over HTTP; it needs path and credential authorization and a measured large-push route. A Cloudflare-managed *zone* can impose a request-body limit, but this account uses workers.dev. MCP resumable streams need a stream identity and replay mapping; browser SSE needs an expired-cursor rule. A supplied invalid MCP Origin must be rejected with HTTP 403. Authenticate and authorize the principal and repository **before** WebSocket upgrade and bind that identity to the socket. For hosting costs, distinguish WebSocket hibernation from SSE/MCP response duration and specify Bun's 120-second default idle timeout, keepalive, payload and *backpressure* (slowing sends when a client cannot keep up). *Recovery loss window* means accepted work that could be lost after failure; its target remains for the owner to choose (Platform source notes; Platform report; v3 on Cloudflare, October 15–16).

**Task-copy cost and cleanup.** Artifacts storage billing averages each day's peak bytes over the billing period, while capacity follows maximum simultaneous bytes. An Artifacts delete request returning HTTP 202 means accepted, not reclaimed. The hosting comparison must estimate daily peaks under bursts, count delayed deletion and confirm disappearance in inventory and billing before crediting savings. One-hour task copies cannot automatically be priced as one twenty-fourth of a day's peak (Concord v3 on our current Cloudflare setup, “Comparable monthly components,” October 15–16).

**Scope and evidence limits.** The 20-agent/ten-repository load is hypothetical; the 200-socket measurement is a local 60-second Node prototype, and the separate simulated-hour check is a proposed test. Published host prices are dated quotes, not an MVP sizing result. An *estimate* is a calculated scenario; an *observation* is a measured result at its stated scope. The owner approved the research sequence, not live agent tests or a hosted service (research-phase decision, D-RESEARCH-PHASE; hosted-service-later decision, D-HOSTED-SERVICE-LATER, October 15–16). Label claims observed, estimated, planned or decided in the next draft (design-tracking decision, D-DESIGN-TRACKING).
