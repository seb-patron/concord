# Concord v3 platform audit against research and owner decisions

## Plain summary and answer

**The draft is not yet a reliable statement of the chosen platform.** Its own-forge direction and one-way GitHub mirror match owner decisions. Its single virtual private server (VPS), server runtime, storage placement, cost and migration schedule are proposals presented with more certainty than the evidence permits. In particular, the owner did not approve a host. On October 16 the owner directed a new hosting comparison starting from the live v2 Cloudflare Worker, Durable Objects and Artifacts arrangement, with checker and promoter currently on owner machines; v3 must move the promoter off those machines and test the smallest credible minimum viable product (MVP) host. A hosted service for others waits until after the MVP (owner-decisions-2026-10-16.md; owner-decision-status-2026-10-16.tsv).

This audit covers the draft's platform sections and their cross-cutting statements. A separate audit covers claims, issues, landing, runs, checks and review. Consequently, a reference here to an exclusive code-unit claim, runner isolation or the temporary GitHub path identifies a platform dependency, not a redesign of those subjects. **STRUCTURAL** means a durable design, protocol or owner-policy mismatch. **CAPABILITY-DEPENDENT** means the finding depends on current product or agent capability and should be retested. All observations below are from supplied files dated October 15–16, 2026 unless a row says otherwise; vendor prices and limits are snapshots, not current guarantees.

Terms used below: an *Artifact* is Cloudflare's Git repository service; a *Durable Object* is Cloudflare's stateful Worker component; a *ref* is a Git branch or tag pointer; *compare-and-swap* (CAS) changes a ref only if it still has the expected value; *MCP* is Model Context Protocol, the agent tool transport; *SSE* is server-sent events, a one-way HTTP stream. A GitHub *mirror* copies selected refs outward and cannot restore Concord's database. The October 15 research reports made recommendations, not owner approvals. The later owner decisions govern the draft revision.

## Draft Decisions section: platform entries

The draft's own-forge decision is **answered**: the owner approved an agent-first Concord forge and a one-way GitHub mirror (own-agent-forge decision, D-V3-OWN-AGENT-FORGE; GitHub-work decision, D-NO-GITHUB-WORK; owner-decisions-2026-10-16.md, October 15–16). Earlier Forgejo research favored an adjacent forge, but its feature fit does not override the product choice (sp-a-platform.md; r8-forgejo-gitea-notes.md, October 15). The draft should preserve that decision while qualifying its technical comparison: Forgejo's issues, API, Git and runner facilities exist, but do not implement Concord's semantics; a second login is not inevitable.

The draft's one-VPS hosting item is **superseded as a framing, still open as a choice**. The hosting-from-v2 decision (D-HOSTING-FROM-V2) orders a comparison from the deployed Cloudflare Worker, Durable Objects and Artifacts system. The no-local-promoter decision (D-NO-LOCAL-PROMOTER) sets the MVP placement constraint and rejects the unmeasured large VPS default. The Cloudflare-scale and Artifacts-options decisions (D-CF-V3-SCALE; D-ARTIFACTS-OPTIONAL) keep the existing platform and three Git placements in the comparison. Evidence is in h7-our-cloudflare.md, h8-v3-on-cloudflare.md, h9-cf-account.md, h2-vps-storage-notes.md and hosting-options.md, October 15–16. The owner must still choose host, region, cost ceiling, storage placement and recovery targets.

The runtime item is **still open**. Bun's documented WebSocket/SQLite APIs make it a candidate, and Node's HTTP documentation is another input; neither proves production equivalence, a Node 22 fallback or a minimum Git version (sp-f4-platform-notes.md; r7-node-http-notes.md, October 15). No owner decision in the supplied active status approves the runtime. The first-repositories item is also **still open** as a cutover choice: the draft proposes an order, while the owner's research plan first requires the platform audit and new hosting study (research-plan decision, D-RESEARCH-PLAN-2-GO; owner-decisions-2026-10-16.md, October 16). Later aggregate size checks narrow, but do not settle, Git placement risk (repo-size-check-2026-10-15.md).

The first-swarm-backends item is a **still-open platform interface dependency**; backend sequencing, model choice and monthly cap belong to the second audit. The land-policy and shared-claim items also belong there. In particular, the draft's shared-by-default claim proposal must not be read as reversing the active exclusive-unit decision without a new owner decision (exclusive-unit decision, D-UNIT-1-EXCLUSIVE; owner-decision-status-2026-10-16.tsv, October 16). This audit makes no recommendation on their semantics.

## Research with no clear home in the draft

**Current-state baseline and metering.** The live system uses a Worker, tenant and repository Durable Objects, Artifacts canonical Git and task forks, with Git traffic direct to Artifacts and a local checker/promoter. The four-day account measurements are aggregate, not per repository, and exclude billable Artifacts operation counts. A read-only account check confirmed some services and a partial invoice, while subscription billing details were unavailable. These observations need a current-state diagram and a measured cost ledger, not a forecast inferred from agent API calls (h4-our-usage.md; h7-our-cloudflare.md; h9-cf-account.md, October 15).

**Git placement and correctness.** The October 15–16 study names four placements: Artifacts canonical with server compute, Artifacts only for task copies, server Git/SQLite, and Cloudflare metadata with object storage and Git compute. Artifacts' binding cannot directly mutate refs, but its Git protocol can push; no source proves safe concurrent CAS, exact readback after write or recovery. Artifacts also has a one-gigabyte per-repository and 32-megabyte per-blob documented limit in the supplied capture. A later ten-repository local check found one non-main blob over that blob limit; the data are local Git sizes, not a capacity test or a private-repository inventory for public release (h6-artifacts-notes.md; h8-v3-on-cloudflare.md; repo-size-check-2026-10-15.md, October 15–16). This belongs in deployment, data model and migration gates.

**Recovery, protocol and operating limits.** A one-way GitHub mirror restores only selected refs. Independent backup must cover Git objects and refs, consistent SQLite state, large-file storage, identities and secrets, with tested restore. Git smart HTTP needs its own authorization and large-push route; a proxied Cloudflare zone can impose a request-body limit. Mononoke is a reference design for separating immutable data, mutable refs, derived views, mappings and recovery checks, not a requirement to copy its architecture. MCP stream IDs, WebSocket reconnection, backpressure, browser SSE and public read access each need explicit contracts (r3-mononoke-notes.md; sp-f4-platform-notes.md; hosting-options.md; h1-cloudflare-notes.md, October 15–16).

**Scope and evidence limits.** A hypothetical 20-agent/ten-repository load, the 200-socket local test, published host prices and one-hour idle target are estimates, prototypes or goals. None sizes the MVP. The owner approved a research sequence, not live agent tests or a new hosted service (research-phase decision, D-RESEARCH-PHASE; hosted-service-later decision, D-HOSTED-SERVICE-LATER; owner-decisions-2026-10-16.md, October 15–16). A revised draft should label each claim as observed, estimated, planned or decided and update the source ledger after each research round (design-tracking decision, D-DESIGN-TRACKING).

## Method and limits

I read the supplied draft and all seventeen research files plus the owner decision log and active-status snapshot in full. No web sources were fetched for this audit. The research files themselves include dated vendor-page notes; their quoted limits and prices may change. I did not inspect private repository contents or rerun hosting prototypes. The failed local `npm run -s decisions` command could not produce its `Approved but not live:` list because `tsx` is absent; the supplied October 16 decision log and status snapshot are the decision evidence here. No host, region, runtime, storage placement, backup loss window, import fidelity or production throughput is inferred from these inputs alone.
