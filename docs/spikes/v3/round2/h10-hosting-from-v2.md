# Concord v3 hosting, starting from v2

Research snapshot: 16 October 2026. This is a recommendation for Concord's own minimum viable product (MVP), not a deployment approval. A Worker is Cloudflare's web request handler. A Durable Object is its named, stateful coordinator with SQLite storage. Artifacts is Cloudflare's Git repository service. A *promoter* is the process that merges an approved change and moves the authoritative `main` branch. A *runner* executes checks on a proposed commit. Prices below are monthly **estimates** unless explicitly called observed.

## Plain answer

**Keep the current Cloudflare Worker, repository Durable Objects and Artifacts for the MVP. Add a Cloudflare Container as the hosted Git/check executor and the only process allowed to push canonical `main`.** This is the smallest change from the deployed v2 shape and removes canonical writes from the owner's machines. Do not rent the previously proposed $81.99/month server. An Artifacts write credential stays only with the hosted promoter; agents submit through isolated task repositories or an enforcing gateway. One repository coordinator admits one promotion at a time. The checked commit is read back from Git before a landing is announced. The current Workers Builds source remains Artifacts `main`.

**Estimated monthly price:** about **$10.37 in a deliberately short, 10-second/check scenario**: $5 Workers Paid plan + $0.77 filtered Durable Object *cycle projection* as a rough repeat-month proxy + $1.21 for 3.42 GB Artifacts storage held a full month + $3.39 Container compute. At one minute per check, the same arithmetic is **$20.65**; at five minutes it is **$69.99**. These are scenarios, not a forecast or a bill. They assume 10,000 candidate completions/month, one isolated Standard-1 check job of 10/60/300 seconds **and ten seconds of separate trusted promotion work per candidate**, possibly split around the check, full sleep between jobs, no other Container usage, unchanged v2 request/row patterns, no retry, and no additional Artifacts storage. Charging promotion work for every candidate is conservative because some checks fail. A promoter may take more or less than ten seconds. Artifacts operation units, actual check duration, container start/idle time, Git transfer, backup versions, taxes and any other account usage are **unknown**. The plan is already paid; its $5 is an account floor, not an extra $5 per repository. The 10,000-candidate figure is an activity proxy from the run records below, not 10,000 proven lands.

**Recommendation gate:** use this all-Cloudflare shape only after a disposable implementation proves that a single hosted promoter can submit, check, push, read back, crash, and reconcile without announcing the wrong commit. This is a structural correctness gate, not a new measurement authorized by this report. If that path cannot be made safe or a required repository breaks Artifacts limits, use the small-server shape below. An EU Hetzner CX23 is **$6.49/€5.49 per month** before value-added tax (VAT) and IPv4. With Workers Paid and the same ten-second Container check scenario, its steady-state floor is **about $12.82/month** after Artifacts retirement, plus backup, transfer, tax, IPv4 and unmeasured overage. No supplied measurement proves this small server can handle the workload. The owner chooses host/region and recovery targets before deployment. The hosting-from-v2 decision (D-HOSTING-FROM-V2), no-local-promoter decision (D-NO-LOCAL-PROMOTER), Cloudflare-scale decision (D-CF-V3-SCALE) and Artifacts-options decision (D-ARTIFACTS-OPTIONAL) are the basis for this recommendation.

The finding that v2 already supplies a useful control plane is **STRUCTURAL** (built topology in `h7-our-cloudflare.md`, 15 October). The finding that Container Git/check work and its bill will fit this scenario is **CAPABILITY-DEPENDENT** (Cloudflare prices fetched 16 October; no v3 hosted benchmark). The owner approved research, not a cloud experiment or new spend (research-phase decision, D-RESEARCH-PHASE; round-two plan decision, D-RESEARCH-PLAN-2-GO).

## What runs today

**STRUCTURAL — deployed topology, 15 October source.** One `concord` Worker serves the public API and browser assets on a `workers.dev` address. A TenantCatalog Durable Object holds each tenant's repository catalog, quotas and delegated principals. Each logical repository has one RepoCoordinator Durable Object with its own SQLite-backed coordination lane for changes, claims, leases, review, jobs, queue and events. There is also a public-directory object for anonymous discovery. Artifacts holds canonical Git history, a fork for each new change and scratch repositories for composition. Git clients clone, fetch and push directly to Artifacts over HTTPS; the Worker does not process Git packs. The checker and promoter run on the owner's machines, obtain Git credentials, and the promoter conditionally pushes `main`. Workers Builds deploys the live Worker from Artifacts canonical `main`. GitHub is an optional one-way mirror. Source: `h7-our-cloudflare.md`, “Architecture as built,” 15 October; `h9-cf-account.md`, 15 October; the Workers Builds decision (D-DEPLOY-WORKERS-BUILDS).

This matters because v3 can keep the Worker for routing and static assets, the tenant catalog, one per-repository ordered coordinator, the Artifacts Git endpoint, and the existing deployment source while changing the location and contract of promotion. Moving everything to a new server would replace working parts before demonstrating a gain. Keeping Artifacts is not a permanent pledge; the optional-Artifacts decision (D-ARTIFACTS-OPTIONAL) explicitly leaves canonical, task-only and no-Artifacts placements open.

**CAPABILITY-DEPENDENT — observed use and bill, 15 October source.** The account-wide October 12–15 extract (plus three early October 16 Worker calls) has 997,407 Worker requests, 1,175,856 Durable Object requests, about 1.12 million Worker CPU milliseconds, 2.656 billion SQL rows read and about 2.275 million written. On October 14, 421,749 object requests read 1.571 billion rows, an average near 3,725 rows per request. These are account totals, not per-repository or per-action measures. At 11:53 a.m. Chicago time on October 15, a separate audit counted 486 Artifacts repositories storing 3.42 GB; a later inventory found 487 repositories. New changes allocate forks, and the current adapter has no delete operation, so those counts cannot be treated as 486 active logical repositories. Source: `h4-our-usage.md`, `h7-our-cloudflare.md`, `h9-cf-account.md`, 15 October.

An idle alarm bug previously caused about 1,133 Artifacts reads/hour, which would have been about $121/month **if** each read billed as one operation for a whole month. The deployed fix sharply reduced the observed rate: the 18:00 UTC hour after deployment recorded 38 Durable Object requests and 38 Artifacts events; each of the next five hours recorded eight of each. That is evidence of improvement, not zero background work or a new monthly rate. The same six-hour series does not identify billable Artifacts operations. Source: `h4-our-usage.md` and `h7-our-cloudflare.md`, 15 October.

The owner's **filtered** Billable Usage screenshot for six cycle days showed **$0.15** billable usage and a **$0.77 projected cycle** in the selected product rows: 1.07 million object requests, 2.21 billion rows read, and 41,360 GB-seconds. Workers requests/CPU and SQL rows were within Paid inclusions; the 69,310 excess object requests rounded to a $0.15 line. This is neither an all-product invoice nor the plan charge. Artifacts rows were not visible, and the read-only account token could not retrieve subscription details. The Paid inclusions in the screenshot identify the current plan. The account has no Cloudflare zone and uses `workers.dev`; a Free/Pro *zone* push limit does not describe today's Git path. Source: `h9-cf-account.md`, 15 October.

Workers Paid is [**$5/account/month**](https://developers.cloudflare.com/workers/platform/pricing/) with 10 million requests and 30 million CPU-ms included. Durable Objects include [one million requests, 400,000 GB-seconds, 25 billion SQL rows read, 50 million written and 5 GB-month storage](https://developers.cloudflare.com/durable-objects/platform/pricing/); excess object requests round in million-unit blocks. Artifacts includes [10,000 operations and 1 GB-month](https://developers.cloudflare.com/artifacts/platform/pricing/), then $0.15/1,000 operations and $0.50/GB-month. All pages fetched 16 October 2026; their page dates are 2 October, 30 September and 1 October respectively. The $1.21 storage calculation is `(3.42 - 1) × $0.50` for a hypothetical full month at the observed storage level. Actual Artifacts billable units and retention are unmeasured.

## What v3 needs

The numbered needs follow the **repaired** platform audit and tracker, not the unrepaired architecture draft. “Land” means merge a checked change into canonical `main`. “Exact commit” means the commit tested is the one published. Labels distinguish enduring design constraints (**STRUCTURAL**) from current capability or workload assumptions (**CAPABILITY-DEPENDENT**). Audit and tracker: `a0b-audit-platform.md` and `a0b-tracker-platform.tsv`, 16 October; draft: `concord-v3-architecture.html`, 15 October.

1. **STRUCTURAL — one hosted writer moves main.** One place merges a change, checks the merged result, and moves `main`; no promoter or canonical write credential is on the owner's machines. The server serializes a repository's ref move. “Two agents racing to update main” is not the v3 threat model; two mistakenly active promoter processes would be. Source: repaired audit, 16 October; no-local-promoter decision (D-NO-LOCAL-PROMOTER).
2. **STRUCTURAL — safe Git submission.** Agents can submit proposed Git work but cannot receive a canonical Artifacts write token, because that token is repository scoped rather than proven ref scoped. An isolated task repository or enforcing Git gateway holds that boundary. Git objects must exist and be readable before the coordinator advertises a new ref. Source: `h6-artifacts-notes.md`, 15 October; repaired audit, 16 October.
3. **STRUCTURAL — checks on the exact merged commit.** A hosted scheduler gives isolated runners a commit ID, records the result against it, and rechecks if a stale base changes the merged commit. The policy for fast checks and full batches remains a design choice. Runners must not hold promoter credentials. Source: repaired audit and `f4-platform-report.md`, 15–16 October.
4. **STRUCTURAL — metadata and Git recover together.** Changes, issue claims, code-unit claims, queue, review, events, identity and Git refs cannot disagree after a crash. An intent, ref readback and idempotent reconciliation bridge separate stores. A GitHub mirror contains selected Git refs, not the metadata database. Source: repaired audit, 16 October.
5. **CAPABILITY-DEPENDENT — bounded client and event paths.** Agent-facing HTTP, command-line and Model Context Protocol (MCP) operations need actual authorization and read limits. Browser WebSockets need authentication before upgrade, durable replay and reconnect. Hibernatable object sockets may avoid idle duration; server-sent events (SSE) and pending MCP streams can keep a Durable Object active. The 200-socket/60-second zero-traffic result was a local Node fixture, not hosted billing evidence. Source: `sp-c-realtime-api.md`, `f4-platform-report.md`, 15 October; repaired audit, 16 October.
6. **STRUCTURAL — owner policy and public/private boundaries.** Cloudflare Access first, then passkeys for people; path modes for agent edit, human approval and human-only work; anonymous reads only when a repository's public flag permits them. Every Git, API and event route must enforce repository scope. Source: owner decisions and repaired audit, 12–16 October (login-access decision, D-LOGIN-ACCESS; login-passkeys decision, D-LOGIN-PASSKEYS; path-protection decision, D-PATH-PROTECTION; public-flag decision, D-PUBLIC-FLAG).
7. **STRUCTURAL — deploy and mirror follow the real main.** Workers Builds currently reads Artifacts `main`. If canonical Git moves, deployment needs a replacement source and a cutover test before removing Artifacts. GitHub receives only selected refs through a one-way, retryable mirror with visible lag; it is not the work queue. Source: `h7-our-cloudflare.md`, repaired audit, 15–16 October; no-GitHub-work decision (D-NO-GITHUB-WORK).
8. **STRUCTURAL — backup, restore and lifecycle.** Keep versioned, encrypted Git objects/refs and consistent metadata/identity backups outside the primary provider's account; test a restore to a new host. Delete old task repositories and confirm disappearance after Artifacts' asynchronous deletion. The owner has not set a permitted loss window or restore time. Source: `h6-artifacts-notes.md`, `h8-v3-on-cloudflare.md`, repaired audit, 15–16 October.

These needs do **not** assume a public hosted multi-tenant service or sales before the MVP (hosted-service-later decision, D-HOSTED-SERVICE-LATER). None of ten checked local repositories uses Git Large File Storage (LFS); LFS is optional future scope, not an MVP service. The own-agent-forge decision (D-V3-OWN-AGENT-FORGE) keeps changes and server landing as the product model; it does not settle a host.

import collections, datetime as dt, json, os, pathlib, re
root=pathlib.Path(os.environ["DELEGATE_SCRATCH_DIR"]).parents[2]

for path in root.glob("*/*/status.json"):
    m=re.search(r"20[0-9]{6}T[0-9]{6}Z",path.parent.name)

        end=dt.datetime.fromisoformat(obj["updated_at"].replace("Z","+00:00"))

    except (OSError,ValueError,KeyError,TypeError): continue

active=peak=0

days=[(lo+dt.timedelta(days=i)).date() for i in range(6)]
print("window_intervals",n,"active_repos",len(starts),"peak_overlap",peak)
print("starts_daily","/".join(str(daily[d]) for d in days))
print("candidate_finishes",sum(finishes.values()))
for rank,(repo,count) in enumerate(starts.most_common(),1):
    print(chr(64+rank),count,"/".join(str(finishes[repo,d]) for d in days))
'

**Why A first.** It keeps more of the installed v2 path, removes the local promoter, uses the same Artifacts Git remote and Builds source, and pays for short hosted compute when used. The ability to implement and operate this safely is **CAPABILITY-DEPENDENT** (Artifacts docs 15–16 October); the server-only-main rule is **STRUCTURAL** (owner decision 16 October).

**What changes the choice.** Choose B if the checked repository cannot fit Artifacts, the side-branch blob must be imported unchanged, the only-writer credential boundary cannot be enforced, or crash/restart cannot reconcile an uncertain push and exact checked commit. If small-server pack CPU, RAM or transfer proves insufficient, increase only the measured bottleneck or keep Cloudflare.
