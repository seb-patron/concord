# Concord v3 hosting, starting from v2

**Answer in plain language:** Keep the Cloudflare web service, repository coordinators and Git storage that v2 already uses. Move the program that publishes approved changes from the owner's machines to a hosted process, and run checks in isolated hosted jobs. A Cloudflare Container is the smallest first shape to evaluate. It is acceptable only if an old publisher loses write power before a replacement starts, even when the old process pauses and later resumes. If that cannot be proved at the Git endpoint, use a small hosted server with an enforceable write path. Prices below are estimates; no host has measured capacity for this workload.

Research snapshot: 16 October 2026. This recommends a host for Concord's own minimum viable product (MVP); it approves no deployment. A Cloudflare *Worker* handles web requests. A *Durable Object* is a named coordinator with an embedded SQLite database, which stores records in tables. *Artifacts* is Cloudflare's Git repository service. A *promoter* merges an approved change and moves the authoritative `main` branch; a *runner* executes checks. **STRUCTURAL** marks a lasting safety or policy requirement. **CAPABILITY-DEPENDENT** marks dated prices, product behavior, workload observations or untested fit, to revisit later. All monthly prices are **estimates** unless called observed.

Reading key: A *Container* is a disposable hosted process; its disk is temporary. A *task repository* holds one agent's proposed work. An *enforcing gateway* accepts Git requests and applies Concord's authorization policy. The *control plane* is the Worker and coordinators that decide who may do what; a *tenant* is an owning account, and a *delegated principal* is an authenticated agent acting for it. An application programming interface (*API*) is a program-facing route; Hypertext Transfer Protocol Secure (*HTTPS*) encrypts web traffic. Git transfers compressed history in a *pack*; a *scratch repository* temporarily holds a composed candidate. A *ref* is a branch pointer. *Readback* fetches that pointer after a push. *Workers Builds* deploys the Worker from a Git branch. Other terms are explained where they first affect a choice.

Capacity terms: a *virtual CPU* (vCPU) is a server's allocated processor share; *random-access memory* (RAM) is working memory; a *gibibyte* (GiB) is 1,024³ bytes. *Egress* is outbound data transfer. A virtual machine (*VM*) or virtual private server (*VPS*) is a rented server; its operating system (*OS*) needs patching. A Worker *isolate* is its bounded execution environment. *R2* is Cloudflare object storage: an *immutable object* is a stored value that never changes, while a Git *ref* can move. *Pack assembly* builds compressed Git transfers; *object reachability* means refs keep required Git objects available. *Git smart HTTP* carries clone, fetch and push; its *receive-pack* operation accepts pushes. *Ingress* is incoming traffic, *TLS* encrypts its connection, and a *failure domain* is infrastructure that can fail together. An *out-of-band writer* bypasses Concord's promotion gate. A *binding method* is a Worker call to a service. Below, *DO* abbreviates Durable Object.

## Plain answer

**Start with the deployed Worker, repository Durable Objects and Artifacts; evaluate a Cloudflare Container for hosted Git promotion and isolated checks.** This is the smallest proposed change from v2 and removes canonical writes from the owner's machines. It is **conditional**: the hosted write gate must prove that a stale or replaced promoter can never move canonical `main`, including after it resumes. A repository coordinator's admission decision and a later readback alone cannot enforce this. Agents use isolated task repositories or a gateway, never a canonical write credential. If Artifacts cannot enforce the required conditional write and revocation contract, use a hosted server with an enforcing Git receive path; keep the Worker and Artifacts where useful. Workers Builds currently reads Artifacts `main`.

**Estimated monthly price:** **$10.35 / $20.63 / $82.47** with 10,000 candidate jobs and checks lasting 10/60/300 seconds, respectively. These account-level scenarios include the $5 Workers Paid floor, a transparent $0.75 projection of existing Durable Object request overage, a $1.21 Artifacts storage proxy, Container compute, and the Container objects' requests and active duration. At five minutes, the shared Durable Object duration allowance is exceeded and a rounded **$12.50** block appears. The owner's filtered **$0.77 cycle projection** is an observation, not an additive tariff line; it is replaced by the explicit repeat-month model below. The check and promoter each sleep immediately after work in this estimate, and each Container object waits synchronously for its job. If it can hibernate during the job, the duration result falls; neither behavior is measured. Gateway cost, Artifacts operation units, actual job/idle seconds, transfer, backup, retries, taxes and other account use remain unknown. The $5 is an account floor, not a charge per repository. Ten thousand candidate finishes are an activity proxy, not proven landings.

**Recommendation gate:** before using Artifacts as canonical Git, prove an enforceable write fence at the actual Git write endpoint. Pause an admitted old promoter; admit a replacement only after old authority is revoked and in-flight writes are accounted for; resume the old process. Also test uncertain push acknowledgement and coordinator restart. In every order, the old process must fail to move `main`. The endpoint must reject a push unless its expected old ref matches; the replacement must rebuild and recheck the exact new commit after any stale base. Readback and intent recovery must match the checked commit before announcing landing. A disposable proof is a future experiment needing separate approval. Hetzner lists an EU CX23 at **$6.49/€5.49**, excluding value-added tax (VAT) and optional public Internet Protocol version 4 (IPv4), but its product page marks it unavailable on this fetch. An officially listed DigitalOcean Basic server is a small comparison, with 2 GB memory at **$12/month** or 4 GB at **$24/month**; neither has measured Concord fit or verified region stock. The owner selects host, region and recovery targets before deployment. The hosting-from-v2 decision (D-HOSTING-FROM-V2), no-local-promoter decision (D-NO-LOCAL-PROMOTER), Cloudflare-scale decision (D-CF-V3-SCALE) and Artifacts-options decision (D-ARTIFACTS-OPTIONAL) govern this recommendation.

## What runs today

**CAPABILITY-DEPENDENT — deployed topology, 15 October source.** One `concord` Worker serves the public API and browser assets on a `workers.dev` address. A TenantCatalog Durable Object holds each tenant's repository catalog, quotas and delegated principals. Each logical repository has one RepoCoordinator Durable Object with its own SQLite-backed coordination lane for changes, claims, leases, review, jobs, queue and events. There is also a public-directory object for anonymous discovery. Artifacts holds canonical Git history, a fork for each new change and scratch repositories for composition. Git clients clone, fetch and push directly to Artifacts over HTTPS; the Worker does not process Git packs. The checker and promoter run on the owner's machines, obtain Git credentials, and the promoter conditionally pushes `main`. Workers Builds deploys the live Worker from Artifacts canonical `main`. GitHub is an optional one-way mirror. Sources: **How Concord v2 uses Cloudflare today** (`h7-our-cloudflare.md`), “Architecture as built,” and **Our Cloudflare account** (`h9-cf-account.md`), 15 October; the Workers Builds decision (D-DEPLOY-WORKERS-BUILDS).

This matters because v3 can keep the Worker for routing and static assets, the tenant catalog, one per-repository ordered coordinator, the Artifacts Git endpoint, and the existing deployment source while changing the location and contract of promotion. Moving everything to a new server would replace working parts before demonstrating a gain. Keeping Artifacts is not a permanent pledge; the optional-Artifacts decision (D-ARTIFACTS-OPTIONAL) explicitly leaves canonical, task-only and no-Artifacts placements open.

**CAPABILITY-DEPENDENT — observed use and bill, 15 October source.** The account-wide October 12–15 extract (plus three early October 16 Worker calls) has 997,407 Worker requests, 1,175,856 Durable Object requests, about 1.12 million Worker central processing unit (CPU) milliseconds, 2.656 billion SQLite rows read and about 2.275 million written. ## What v3 needs

The needs follow **Concord v3 platform audit** (`a0b-audit-platform.md`) and its **design tracker** (`a0b-tracker-platform.tsv`), 16 October, rather than the earlier architecture draft. “Land” means merge a checked change into canonical `main`; “exact commit” means the tested commit is published.

1. **STRUCTURAL — one hosted writer moves main.** One place merges a change, checks the merged result, and moves `main`; no promoter or canonical write credential is on the owner's machines. The server serializes a repository's ref move. “Two agents racing to update main” is not the v3 threat model; two mistakenly active promoter processes would be. Source: repaired audit, 16 October; no-local-promoter decision (D-NO-LOCAL-PROMOTER).
2. **STRUCTURAL — safe Git submission.** Agents can submit proposed Git work but cannot receive a canonical Artifacts write token: its scope covers the repository, not only a chosen branch/ref. An isolated task repository or enforcing Git gateway holds that boundary. Git objects must exist and be readable before the coordinator advertises a new ref. Source: **Cloudflare Artifacts documentation study** (`h6-artifacts-notes.md`), 15 October; **Concord v3 platform audit**, 16 October.
3. **STRUCTURAL — checks on the exact merged commit.** A hosted scheduler gives isolated runners a commit ID, records the result against it, and rechecks if a *stale base* (an earlier `main`) changes the merged commit. The policy for fast checks and full batches remains open. Runners must not hold promoter credentials. Source: **Concord v3 platform audit**, 16 October.
4. **STRUCTURAL — metadata and Git recover together.** Changes, issue claims, code-unit claims, queue, review, events, identity and Git refs cannot disagree after a crash. A durable *intent* records the planned move; *idempotent reconciliation* safely retries it after an uncertain result, using ref readback and the exact checked commit. A GitHub mirror contains selected Git refs, not the metadata database. Source: **Concord v3 platform audit**, 16 October.
5. **CAPABILITY-DEPENDENT — bounded client and event paths.** Agent-facing HTTP, command-line and Model Context Protocol (MCP) operations need authorization and read limits. A *WebSocket* is a two-way connection; its *upgrade* establishes it. It needs authorization first, stored-event *replay* after reconnect and a cursor for the last event seen. *Hibernation* lets an eligible idle object stop active billing; server-sent events (SSE), a one-way stream, and pending MCP streams may keep it active. The 200-socket/60-second zero-traffic result was a local Node.js JavaScript test, not hosted billing evidence. Source: **Concord v3 platform audit**, 16 October.
6. **STRUCTURAL — owner policy and public/private boundaries.** Cloudflare Access, its identity gate, comes first, then device-bound *passkeys* (cryptographic sign-in credentials) for people; path modes cover agent edit, human approval and human-only work. Anonymous reads require a repository public flag. Every Git, API and event route enforces repository scope. Source: **Owner decisions**, 12–16 October (login-access decision, D-LOGIN-ACCESS; login-passkeys decision, D-LOGIN-PASSKEYS; path-protection decision, D-PATH-PROTECTION; public-flag decision, D-PUBLIC-FLAG).
7. **STRUCTURAL — deploy and mirror follow the real main.** Workers Builds currently reads Artifacts `main`. If canonical Git moves, deployment needs a replacement source and a cutover test before removing Artifacts. GitHub receives only selected refs through a one-way, retryable mirror with visible lag; it is not the work queue. Sources: **How Concord v2 uses Cloudflare today** and **Concord v3 platform audit**, 15–16 October; no-GitHub-work decision (D-NO-GITHUB-WORK).
8. **STRUCTURAL — backup, restore and lifecycle.** Keep versioned, encrypted Git objects/refs and consistent metadata/identity backups outside the primary provider's account; test a restore to a new host. Delete old task repositories and confirm disappearance after Artifacts' asynchronous deletion. The owner has not set a permitted loss window or restore time. Sources: **Cloudflare Artifacts documentation study**, **Concord v3 on our current Cloudflare setup**, and **Concord v3 platform audit**, 15–16 October.

These needs do **not** assume a public hosted multi-tenant service or sales before the MVP (hosted-service-later decision, D-HOSTED-SERVICE-LATER). None of ten checked local repositories uses Git Large File Storage (LFS), which stores large content separately from Git; it is optional future scope, not an MVP service. The own-agent-forge decision (D-V3-OWN-AGENT-FORGE) keeps changes and server landing as the product model; it does not settle a host.

**Canonical safety gate for all shapes.** The *promotion fence* is a durable generation number and authorization rule for the only canonical writer. The repository coordinator records `(generation, expected old main, candidate commit, check result)` before issuing authority. For A/H, a gateway must retain the Artifacts repository-wide write token and prevent any direct bypass. The gateway revokes the old writer generation, and the Artifacts credential issuer revokes any direct write credential the old process could have held. All authenticated or in-flight old-generation pushes must finish or be provably rejected at the Git endpoint **before** replacement admission. Artifacts must reject an expected-old-ref mismatch at that endpoint. For B, enforce generation and expected-old-ref checks at the server Git receive path; old server processes cannot have a bypass credential. A paused old promoter must not push after replacement admission even if it resumes before the replacement pushes. Kill/revoke acknowledgement, in-flight drain and stale-token rejection are **unproved** on Artifacts. If they cannot be proved, A/H fail the gate regardless of readback. Test coordinator restart, old-process resumption and uncertain push acknowledgement. After an uncertain acknowledgement, stop admission and read `main`: if it equals the checked commit, reconcile the recorded intent; if it differs, quarantine and rebuild against the observed base. Any changed base requires a new merged commit and **new exact-commit checks**. Announce landing only after readback equals that checked commit. No out-of-band canonical writer may exist.
