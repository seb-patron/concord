A presence holder can **request an atomic upgrade** before its first protected edit, before a destructive operation, or after repeated measured conflict. The server checks policy and current exclusive holder/fence, grants a fresh fence or queues the request; presence alone gives no place ahead of existing FIFO waiters. Other presence holders can still edit optimistically, but their publish to that now-exclusive unit must be refused unless they acquire a valid fence or policy permits optimism. Upgrading after writing risks wasted work, so nonmergeable assets need exclusion **before edit**. Release/downgrade at submit/cancel; an expired holder must re-read and rebase. These are proposed protocol rules inferred from Chubby fencing, Git LFS verification and Gray conversion ordering (`s1-leases-lockservices-notes.md`, “The Chubby lock service,” 2006; `sp-f1-locks-notes.md`, “Git LFS File Locking API,” read 2026-10-15; `r11-lock-papers-notes.md`, “Granularity of Locks and Degrees of Consistency,” 1976). **STRUCTURAL (source dates: 1976, 2006, 2026-10-15 read):** a claim without downstream verification cannot enforce exclusion.

### C. Issue-declared leases and ready-set scheduling

A versioned issue/spec may declare `{unit, mode, reason, confidence, source, policyVersion}`. Source can be a human spec author, an AI prediction from issue/code context, or similar historical changes. Claiming the issue atomically owns the **task identity** and attempts the declared unit claims, recording granted/queued/omitted units; task ownership alone does not block a source edit. When work strays, the agent proposes a **widen** with diff and reason. The server auto-grows if policy allows and unit is free, queues/notifies if contested, requests owner decision only for a protected-scope policy exception, and refuses publication of undeclared protected edits. Keep original and revised declarations for audit. This follows decided declare/grow/verify (D-LEASE-Q5-CPLUS) but is a testable protocol proposal, not deployed behavior (`docs/decisions.md`, “D-LEASE-Q5-CPLUS,” 2026-10-12; `s2-agent-coordination-notes.md`, “/agent-company,” read 2026-10-15; `concord-v3-architecture.html`, “Issues and dependencies,” 2026-10-15). **STRUCTURAL (source date: 2026-10-15):** an issue claim cannot itself enforce a source-unit gate.

The scheduler can first honor issue dependencies, then choose ready issues whose **declared exclusive** units do not collide while allowing presence overlaps. Do not treat a declared intersection as certain conflict. In S5, 10,513 runs had declarations, 5,367 had diffable commits; 19,814/26,494 declared file entries changed (74.8%), 6,680 did not (25.2%); 1,403/10,513 were marked refused scope. The raw output's 3,592,610 same-repo overlapping approximate intervals have 896,897 declared-path overlaps (25.0%) and 66,728 actual changed-path overlaps (1.9%). Its prose report names a different interval-pair denominator (3,800,963); resolve that discrepancy before simulation. Accepted commits cannot exceed their allowed list because the launcher enforced it. Authors already knew the code, so this is **not blind prediction recall** or a causal estimate of lease value (`s5-declared-footprints.md`, “Declared and actual worker footprints,” 2026-10-15; `s5-output.txt`, “Declared vs actual worker footprints,” 2026-10-15). **STRUCTURAL (source date: 2026-10-15):** automatic exclusion on all declarations would serialize many pairs without actual shared changed paths. **CAPABILITY-DEPENDENT (source date: 2026-10-15; re-test with current agents):** independent issue-to-footprint prediction remains unmeasured.

### D. Agent coordination and events

Return holder/session, issue, intent, unit, mode, base, expiry/fence, contact route, wait position and an **uncertain** ETA based on expiry. A contender may notify/message the holder, work elsewhere, enter the FIFO line, wait for a queued change, or rebase on the exact landed commit. Required resumable events: `claim.granted/denied/upgraded/renewed/released/expired`, `wait.position/granted/cancelled`, `change.queued/landed/failed/ejected`, `session.disconnected/resumed`, `issue.ready/blocked`, and `policy.changed`; sequence them, deduplicate message IDs, and allow state refresh after missed events. A notification is never a grant. Agent Mail provides holder/conflict messaging; Chubby supplies session/event precedent; queue systems show predecessor invalidation (`s2b-agent-mail-notes-part1.md`, “MCP Agent Mail,” read 2026-10-15; `s1-leases-lockservices-notes.md`, “The Chubby lock service,” 2006; `r1-scion-queues-notes.md`, “Managing a merge queue,” read 2026-10-15; `concord-v3-architecture.html`, “Events and zero idle cost,” 2026-10-15). **STRUCTURAL (source dates: 2006, 2026-10-15 read):** events are hints to refresh state; the server owns final grant and land validity.

Whether current agents notice presence, message usefully, wait at the right time, or rebase efficiently is **CAPABILITY-DEPENDENT (source date: 2026-10-15 read; re-test with current agents)**. Cursor's earlier task-lock observations cannot answer it (`sp-f1-locks-notes.md`, “Scaling long-running autonomous coding — Cursor,” read 2026-10-15).

### E. Contention and liveness

For exclusive units, use FIFO per unit, never letting later automatic arrivals overtake a waiter. If reader-writer modes exist, grant compatible head groups. On **one central server**, add a waits-for edge to each blocking holder/earlier incompatible waiter; accept the wait unless it closes a cycle, then return the cycle and let the requester release/replan. Rosenkrantz section 14 uses this central dynamic WAIT, while wait-die/wound-wait serve distributed sites without the global graph (`rosenkrantz-notes.md`, “System Level Concurrency Control for Distributed Database Systems,” 1978, section 14; `r11-lock-papers-notes.md`, “Granularity of Locks and Degrees of Consistency,” 1976). **STRUCTURAL (source dates: 1976, 1978):** central cycle detection avoids deadlock without needless restart on every conflict. Coding-session restart cost is a hypothesis to measure.

Alternatives: **all-at-once atomic claims** avoid deadlock if a complete footprint is known, but overclaim or block at start; **ordered claims** by canonical key permit incremental acquisition but discovery of a lower key may require release/restart; **dynamic grow plus cycle check** permits incremental work at the cost of graph management. Expiry/grace need a server clock, renewal before deadline, fresh fence after expiry, and stale publish rejection. A disconnect can get a bounded grace, not indefinite ownership; a live abandoned connection also needs expiry. Gray–Cheriton shows the renewal-versus-delay trade and Chubby demonstrates grace/fencing; neither validates the draft's ten minutes (`s1-leases-lockservices-notes.md`, “Leases: An Efficient Fault-Tolerant Mechanism,” 1989, and “The Chubby lock service,” 2006; `rosenkrantz-notes.md`, “System Level Concurrency Control,” 1978). **STRUCTURAL (source dates: 1978, 1989, 2006):** expiry without a publication fence is unsafe.

Human controls: inspect, bump, force-release/revoke with reason, pause new grants or landing, cancel/reassign, and per-path policy. Human-only force-release/move-to-front/pause and long renewal are recorded decisions; do not re-ask them. A bump can invalidate speculative queue results (`docs/decisions.md`, “D-LEASE-WAIT-LINE,” “D-LEASE-LONG-TTL,” “D-AGENT-FIRST-HUMAN-CONTROLS,” 2026-10-13/14; `r1-scion-queues-notes.md`, “Managing a merge queue,” read 2026-10-15). **STRUCTURAL (source date: 2026-10-15 read):** priority reordering is not free.

### F. Hybrids and merge alternatives

1. **Presence by default plus policy exclusivity** on selected nonmergeable/high-cost assets, with a fenced server gate. Perforce/Unity/LFS support selective asset protection, but this default would reverse D-UNIT-1-EXCLUSIVE (`sp-f1-locks-notes.md`, “Perforce file type modifiers,” “Unity lock rules,” and “Git LFS File Locking API,” read 2026-10-15; `docs/decisions.md`, “D-UNIT-1-EXCLUSIVE,” 2026-10-14).
2. **Optimistic first, escalate hot units** after bounded observed conflict/repair cost. Do not learn from future replay conflicts. Kung–Robinson frames wait versus retry; SP-F5 adaptive missed five textual conflicts and blocked ten clean pairs (`sp-f1-locks-notes.md`, “On Optimistic Methods for Concurrency Control,” 1981; `sp-f5-replay.md`, “SP-F5,” 2026-10-15). **STRUCTURAL (source dates: 1981, 2026-10-15):** hotness trades false blocks against misses, never proves correctness.
3. **Union merge for allowlisted append-only indexes**, then canonicalize/deduplicate and verify format/order; otherwise ordinary merge/repair. Raw union removed 32/40 replay conflicts but left eight; Git says union ordering can be arbitrary (`sp-f5-replay.md`, “SP-F5,” 2026-10-15; `r10-funcname-treesitter-notes.md`, “gitattributes — Built-in merge drivers,” read 2026-10-15). **STRUCTURAL (source date: 2026-10-15):** clean text does not prove ordered-log or semantic validity.
4. **Structured merge at land** as opt-in, preserving original conflict, resolver output and full checks, with Git/manual fallback. This is already D-UNIT-4-STRUCT-MERGE. Mergiraf resolved 3/44 conflicted files in replay and requires usable base/diff3 input (`sp-f5-replay.md`, “SP-F5,” 2026-10-15; `r5-jj-merge-piper-notes.md`, “Usage — Mergiraf,” read 2026-10-15; `docs/decisions.md`, “D-UNIT-4-STRUCT-MERGE,” 2026-10-14). **STRUCTURAL (source date: 2026-10-15):** resolver success is not semantic proof.

## 3. What the replay shows and does not show

SP-F5 evaluated 1,304 deterministically selected overlapping **merged-PR** pairs from five repositories (all 104 Concord pairs and 300 from each of four others), using each PR's **final head** and a shared merge base. Ordinary `merge-tree` found 40 textual-conflict pairs; 36 involved append-only index/log files, seven code and three docs (classes can overlap). File exclusion blocked 241 pairs, 201 of which merged cleanly. Git funcname and interface/body had that same aggregate; tree-sitter blocked 234, 194 clean; hunk ranges blocked 59, 19 clean; adaptive blocked 45, ten clean, and missed five. Zero-miss values mean **within this sample and textual criterion**, not correctness (`sp-f5-replay.md`, “SP-F5: larger lock-scheme replay,” 2026-10-15; `sp-f5-output.txt`, “SP-F5 lock-scheme replay,” 2026-10-15). **STRUCTURAL (source date: 2026-10-15):** these are properties of the replay, not observed live lease outcomes.

The reported “pairwise serial delay” sums each blocked pair's overlap from PR `created_at` to `merged_at`; **PR-open time is not agent-working time**. It includes review/CI/idle intervals and can count one PR repeatedly. Final heads can contain edits made after the overlap began. Policy schemes see **perfect-foresight final footprints**, not what an issue could have declared at dispatch.
