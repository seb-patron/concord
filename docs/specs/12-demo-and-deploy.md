# 12 — Reproduce the submission in local or provisioned mode

Budget: 90 minutes of implementation, excluding owner provisioning and filming. Suggested worker: Codex gpt-6-sol. Dependencies: 01–11 integrated. Behavior: one deterministic demo driver produces a truthful, reproducible submission run; mirror and deployment are its gated publication outputs.

## Delegation spec

Goal:
  Outcome: Package the owned synthetic repository, scenario driver, optional one-way human mirror, and deployment preflight so the demo can be repeated from a clean clone.
  Done when:
    - demo/main.ts implements seed, scene <name>, inspect, and preflight commands exactly as DEMO.md. It uses public APIs/CLI, real native Git commits, distinct fixture identities, and a real pinned checker. It never writes directly into coordinator state or injects fabricated PASS results. A --run identifier isolates every rehearsal.
    - The public MIT fixture is dispatch-lab with the exact TSV rows, executable dispatch behavior, fixed trusted acceptance matrix, checker, unit/dependency policy, changes, findings, contest, and safe default flags specified in DEMO.md. The checker invokes the candidate executable and compares outputs and row values with literal case constants held outside candidate forks: ordinary cases require exact values, while one common J contest case pins exact non-epsilon values and admits either complete epsilon `(retry_limit, timeout_ms, output)` tuple `{(2, 500, 1000), (2, 1000, 2000)}` under identical base and profile inputs. Both J children pass the hard gate before scoring. No expected value is calculated from candidate-edited data. Case selection is trusted and pinned to the job profile. Runtime IDs/OIDs are captured in a manifest rather than hard-coded as fake SHAs.
    - Local end-to-end test launches the bridge, Worker, bounded checker/promoter processes, and scenario driver with deterministic synchronization barriers. It demonstrates conflict refusal, disjoint work, failing-singleton isolation with surviving changes landed, full repair, verdict carry/invalidation, contest winner, and seven-attempt dedupe. It proves both J children pass the same pinned hard-gate case before scoring. For the wrong in-range executable result test, claim the `file:dispatch.mjs` fallback unit (mapped to `dispatch.mjs` by the trusted unit policy) and send it through the existing create/claim/publish `unitKeys` and `leaseFences`, with no new request field, so admission accepts the edit and the checker rejects its output without promotion. A separately claimed and declared `row:families:alpha` in-range unintended table edit also fails the pinned case without promotion. All child processes are waited for or stopped in finally blocks.
    - GitHub mirror command defaults to --dry-run, reads the confirmed canonical SHA, and pushes only main to an explicitly owner-supplied demo remote when --execute is authorized. No reverse sync, force push, real-project mirror, PR API, or token in URL/log is allowed. Divergence blocks mirroring. Its failure cannot roll back a Concord merge.
    - deploy:check --local validates config, absence of fixture credentials in production, safe content flags, and local readiness. --remote checks account/Artifacts availability only with owner-supplied credentials. Local absence of account reports remote deployment unavailable, not local failure. Production mode cannot use the fake bridge.
    - Deployment runbook references the early account-time Artifacts create/empty-fork/first-push gate from 02 and its separately created, first-commit-seeded repo fallback. It gives exact dry-run, secrets provisioning, deploy, smoke, and rollback commands. Remote smoke repeats create/fork/push/read, proves stale expected-old rejection, token isolation, and one checked canonical landing, records provider version/URL and immutable SHA, and never substitutes a local fake for deployed evidence.
    - README and DEMO are reconciled with actual commands and honest status; default CONCORD_SHOW_DECOMPILED_C=0 excludes all C/proprietary artifacts. No real historical comparison is claimed without 11's approved input. Account-free local acceptance is complete even if the owner has not provisioned cloud access.
  Inputs:
    - docs/ARCHITECTURE.md, DEMO.md, JUDGING.md, and slice runbooks; integrated implementations 01–11. No Cloudflare account or GitHub mirror destination is assumed.
    - Authorized implementation is local. Account creation, deploy, mirror push, submission upload, and filming are owner/operator actions unless separately granted in the launch prompt. Do not wait for credentials to build/test local packaging.
    - Use the existing synthetic fixtures and small native Git operations; do not install proprietary compilers, export private stores, or invoke agents/models. Screen evidence is generated by the running application, not pre-rendered success cards.
  Deliverables:
    - Demo/checker/policy/AW fixture, scenario manifest driver, preflight/mirror tools, local integration tests, deployment runbook, and corrected user-facing run instructions. Runtime files live in the caller's temporary run directory.
  Stop and escalate when:
    - Live Artifacts disproves a required capability, credentials/spend/publication are not granted for a requested remote action, code rights are unclear, or frozen seams prevent local integration. Keep completed local artifacts and report the exact owner decision. Missing optional historical export or account does not prevent local packaging acceptance.
